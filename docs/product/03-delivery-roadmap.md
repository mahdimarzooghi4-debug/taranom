## ۳. زنجیره رسمی توسعه
`Business → Technical → Scrum/Product Backlog → Sprint → Code → Code Review → Stage → QA/Testing → Release Approval → Production → Monitoring → Improvement`

| دروازه | محصول قابل تحویل و شواهد حداقلی |
|---|---|
| Business | منشور، کاربران، دامنه MVP، نیازمندی‌های قابل ردیابی، تصمیم‌های باز/بسته، معیار پذیرش |
| Technical | معماری، دامنه‌های مالک داده، قراردادهای API، امنیت، ایمنی بالینی و ادغام‌های مجاز |
| Backlog | Epics و Stories و وابستگی‌ها و Definition of Ready |
| Sprint / Code | پیاده‌سازی کوچک و آزمون‌پذیر فقط با قرارداد پذیرفته‌شده |
| Code Review | بازبینی فنی، امنیتی، خطرهای سلامت و شواهد تست |
| Stage | محیط غیرProduction با داده آزمایشی/مجاز و نسخه قابل ردیابی |
| QA / Testing | آزمون سناریو، خطا، مجوز/دسترسی، بازیابی و بررسی بالینی متناسب با حوزه |
| Release Approval | تأیید صریح انسانی صاحب اختیار و ذی‌صلاح بالینی/حقوقی در صورت نیاز |
| Production | استقرار مجاز با شواهد آمادگی و رول‌بک |
| Monitoring / Improvement | پایش کیفیت، پاسخ‌گویی حادثه، بازخورد، تغییرات کنترل‌شده |

## ۴. ترتیب پیشنهادی توسعه (بدون مصوب‌کردن MVP)
1. **Discovery و Business:** استخراج قرارداد عضویت/نقش‌ها و یک Journey پایه از مسئله تا هدایت به انسان.
2. **Technical Foundation:** طراحی هویت، رضایت، ممیزی، داده حداقلی، عملیات و امنیت. تا زمان مجوز، از داده بیمار واقعی استفاده نشود.
3. **نسخه آزمایشی کم‌خطر:** گردش کار اداری/هماهنگی غیرتشخیصی با داده ساختگی و آزمایش‌های قابل اثبات؛ نام «تریاژ درمانی فعال» به آن داده نشود.
4. **بالینی و ارائه‌دهندگان:** فقط پس از تعریف پروتکل، مسئول بالینی، خدمات مجاز و پایلوت کنترل‌شده.
5. **ادغام با بیمه و سلامت:** فقط پس از وجود دسترسی قانونی، قرارداد API و شواهد عملیاتی.
6. **مالی/اعتباری/سرمایه‌گذاری:** یک جریان کاری مستقل و مسدود تا قرارداد قانونی، مالی، حسابداری و تطبیق داده.
7. **گسترش منطقه‌ای و ملی:** پس از پایلوت، سنجش واقعی و تأیید انتشار.

## ۵. اولین بسته کاریِ قابل تأیید
- تکمیل Source Review و Decision Register (همین PR)
- مصاحبه/انتخاب گروه هدف نخست و تعریف ارزش قابل‌سنجش
- تعریف Boundary Map بین مراقبت، تشخیص، پرداخت، بیمه و امور مالی
- تعیین میزان آمادگی شرکای واقعی و دسترسی سامانه‌های بیرونی
- تصویب Business Contract v1 و سپس ایجاد Technical Contract v1

## ۶. خط قرمز
تا تأیید مدارک و متخصصان مربوط، **هیچ تریاژ واقعی خودکار، توصیه تشخیصی/نسخه، دریافت یا سرمایه‌گذاری پول واقعی، تخصیص اعتبار درمانی، فعال‌سازی پوشش بیمه، دسترسی به پرونده واقعی، یا اعلام استقرار ملی انجام نمی‌شود**. نمایش Demo نباید این قابلیت‌ها را واقعی وانمود کند.

## ۷. وضعیت فعلی
- مخزن در ابتدای کار خالی بوده و با README آغاز شده است.
- این بسته صرفاً طرح‌نامه را به اسناد Business تبدیل می‌کند.
- هیچ انتخاب Tech Stack، اجرای CI، سامانه آماده، قرارداد یکپارچه‌سازی یا استقرار صورت نگرفته است.


## بازتعریف راهبرد عرضه با TRN-BIZ-030 — جامع از روز نخست (۲۰۲۶-۱۰-۰۹)
**تصمیم مصوب و مؤخر صاحب ایده:** [TRN-BIZ-030](../decisions/TRN-BIZ-030-comprehensive-day-one-product-scope.md) اعلام می‌کند **تمام حوزه‌های اصلی ترنم باید در روز اول عرضه رسمی حاضر باشند**، نه اینکه نسخه عمومی نخست به یک زیرمجموعه عضویت/پرونده سلامت/کیف پول/هدایت محدود شود.
- **جدول پنج‌ساله بالا فقط خط مبنای سند PDF است، نه تصمیم مصوب عرضه تدریجی.** بازه‌های سال ۱ تا ۵، بدون تصریح صاحب ایده، مجوز حذف قابلیت‌های سال‌های بعد از روز اول عرضه نیستند.
- **ترتیب داخلی اجرای کار** می‌تواند با وابستگی‌ها و دروازه‌های مستقل برای هویت، داده سلامت، مالی، بیمه، مراکز درمانی، بیمارستان مجازی، تریاژ و AI در بسته‌های متعدد برنامه‌ریزی شود؛ اما **هدف عرضه عمومی نهایی یکپارچه و جامع** می‌ماند.
- پیش از هر عرضه واقعی، آماده‌بودن **همه حوزه‌های وعده‌داده‌شده در دامنه روز نخست** همراه با مسئولیت حقوقی، مجوزهای بالینی، کنترل‌های حریم خصوصی و پشتوانه مالی، شواهد QA و Release Approval لازم است؛ **هیچ تاریخ قطعی یا آماده‌بودن فعلی از تصمیم نتیجه گرفته نمی‌شود**.
- ترتیب پیشنهادی توسعه در بخش ۴ این سند **صرفاً ترتیب ساخت داخلی مشروط** است و نباید به‌عنوان «عرضه نسخه ناقص به بازار» تفسیر شود. در صورت عدم آمادگی حوزه حساس، آن حوزه نباید به‌عنوان خدمت واقعی نمایش/فعال شود؛ اعلام عرضهٔ کامل نیز تا رفع مانع انجام نشود.


## بازتعریف گستره نخستین عرضه رسمی با TRN-BIZ-040 — سراسری (۲۰۲۶-۱۰-۰۹)
**مصوبه جدید صاحب ایده:** [TRN-BIZ-040](../decisions/TRN-BIZ-040-national-first-official-launch-subject-to-readiness.md) **گستره جغرافیایی اولین عرضه رسمی ترنم را سراسر کشور** تعیین می‌کند؛ در کنار **حضور تمام قابلیت‌های اصلی محصول از روز نخست** (TRN-BIZ-030) و **برنامه‌ریزی موازی برای هر سه بازار** (TRN-BIZ-028).
- **توسعه منطقه‌ای یا پایلوت کنترل‌شده در نقشه راه PDF، مراحل ساخت/آزمایش و تهیه شواهد آمادگی‌اند، نه جایگزین تصمیم عرضه رسمی ملی**. جدول پنج‌ساله یا ۲۴ ماهه سند منبع، تاریخ یا ترتیب الزام‌آور عرضه عمومی نیست.
- **هیچ اعلام عرضه سراسری واقعی قبل از تکمیل مجوزها، قراردادهای پزشک/مرکز/بیمه، پوشش عملیاتی به اندازه دامنه وعده‌داده‌شده، الزامات حریم خصوصی و ایمنی، شواهد QA، تأیید انتشار و زیرساخت ملی مجاز نیست**. دسترسی حضوری یا پوشش همه شهرها بدون سند نباید وعده داده شود.
- هیچ پایلوت، شهر/استان شروع، شریک، جدول زمانی، شبکه عملیاتی یا قرارداد واقعی با این تصمیم تصویب نشده است؛ Stage و Production همچنان در گیت مربوط به خود قرار دارند.
