## ۲. زنجیره رسمی توسعه
`Business → Technical → Scrum/Product Backlog → Sprint → Code → Code Review → Stage → QA/Testing → Release Approval → Production → Monitoring → Improvement`

| دروازه | محصول قابل تحویل و شواهد حداقلی |
|---|---|
| Business | منشور، کاربران، دامنه MVP، نیازمندی‌های قابل ردیابی، تصمیم‌های باز/بسته، معیار پذیرش |
| Technical | معماری، دامنه‌های مالک داده، قراردادهای API، امنیت، ایمنی بالینی و ادغام‌های مجاز |
| Backlog | Epics و Stories و وابستگی‌ها و Definition of Ready |
| Sprint / Code | پیاده‌سازی کوچک و آزمون‌پذیر فقط با قرارداد پذیرفته‌شده |
| Code Review | بازبینی فنی، امنیتی، خطرهای سلامت و شواهد تست |
| Stage | محیط غیرProduction با داده آزمایشی/مجاز و نسخه قابل ردیابی |
| QA / Testing | آزمون سناریو، خطا، مجوز/دسترسی، بازیابی و بررسی بالینی متناسب با حوزه |
| Release Approval | تأیید صریح انسانی صاحب اختیار و ذی‌صلاح بالینی/حقوقی در صورت نیاز |
| Production | استقرار مجاز با شواهد آمادگی و رول‌بک |
| Monitoring / Improvement | پایش کیفیت، پاسخ‌گویی حادثه، بازخورد، تغییرات کنترل‌شده |

## ۳. ترتیب پیشنهادی توسعه (بدون مصوب‌کردن MVP)
1. **Discovery و Business:** استخراج قرارداد عضویت/نقش‌ها و یک Journey پایه از مسئله تا هدایت به انسان.
2. **Technical Foundation:** طراحی هویت، رضایت، ممیزی، داده حداقلی، عملیات و امنیت. تا زمان مجوز، از داده بیمار واقعی استفاده نشود.
3. **نسخه آزمایشی کم‌خطر:** گردش کار اداری/هماهنگی غیرتشخیصی با داده ساختگی و آزمایش‌های قابل اثبات؛ نام «تریاژ درمانی فعال» به آن داده نشود.
4. **بالینی و ارائه‌دهندگان:** فقط پس از تعریف پروتکل، مسئول بالینی، خدمات مجاز و پایلوت کنترل‌شده.
5. **ادغام با بیمه و سلامت:** فقط پس از وجود دسترسی قانونی، قرارداد API و شواهد عملیاتی.
6. **مالی/اعتباری/سرمایه‌گذاری:** یک جریان کاری مستقل و مسدود تا قرارداد قانونی، مالی، حسابداری و تطبیق داده.
7. **گسترش منطقه‌ای و ملی:** پس از پایلوت، سنجش واقعی و تأیید انتشار.
