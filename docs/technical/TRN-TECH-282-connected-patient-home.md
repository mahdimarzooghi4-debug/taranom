# Connected patient home

Routes `/patient-app` and `/patient-app/` now render a connected home instead of the legacy synthetic dashboard. Figma frame 16:25 defines the layout; the existing AppointmentPage shell and exact local logo/bell/navigation assets are reused. Seven new SVGs are downloaded directly from the source frame, preserving root dimensions (22px search, 18px cross, 20px service icons). Search, hero, six service tiles and finance card retain the source 390px slot geometry.

The page composes existing authenticated owner-scoped profile, appointment and notification GET clients. Greeting uses the self-declared first name; future count includes only Booked records with a future startsAt at load time. The notification dot appears only when the backend supplies a positive unreadCount. It does not acknowledge notifications or imply verified identity, membership, credit, insurance or a live smart-guide response. No new backend authority, selector or write endpoint is introduced.

Reads run concurrently and abort on unmount/reload. Refresh clears old values immediately. Any 401 invalidates the whole overview even if other reads completed successfully. Independent service errors remain unknown rather than becoming false zero counts. An explicit retry is available; the expandable services menu offers refresh and connected account/profile/support/notification links. No token or profile is persisted in browser storage.

The source hero and unavailable medical/referral/financial services remain visible but inactive with clear product status. No clinical assessment, sample patient name, sample credit or fabricated appointment count is shown. Search and booking tiles open the existing publication-gated discovery route, preserving canonical-center rules. The finance card explicitly has no available data. These inactive/error/loading/count/menu states are functional extensions to the source design.

Legacy preview navigation now performs a full navigation back to home, preventing an old sample component from remaining mounted under the home URL. Android source verification expectations follow the new connected route, but no APK is rebuilt or delivered until the remaining product work is complete, per the user's instruction. The old separately delivered preview artifact is not updated by this change.

Verification: member build/typecheck; eight home browser cases cover owner identity/traffic boundaries, no-session/no-request behavior, zero-vs-unknown, session invalidation, partial-service recovery, connected links, Figma geometry/assets at 390px and long-name responsiveness at 320px. Existing discovery/account tests cover navigation compatibility. Browser responses are synthetic test fixtures; no live session or deployed product/device success is claimed.
