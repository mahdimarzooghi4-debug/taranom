## Real problem

The original GitHub Actions workflows use commit-SHA-pinned actions, `global.json` disables .NET SDK roll-forward, and Web apps use npm lockfile v3 with `npm ci --ignore-scripts`. However no single **deterministic, source-bound inventory** validates these inputs together with NuGet versions across src/tests. The PostgreSQL CI service currently uses a mutable **`postgres:18.6` tag**, and NuGet restore lacks a repository NuGet packages.lock.json; a green CI cannot honestly mean byte-identical runtime provenance.

## Accepted implementation and limits

Implement only `tools/policy_checks/check_build_input_inventory.py`, a standard-library **offline read-only** policy/provenance report, with no network, restore, package execution or new dependency. Use a fixed allowlist of all 5 Web applications; bound all JSON sources and reject path symlinks/unsafe paths/duplicate keys; require exact package.json vs lockfile root versions and dependencies, npm lockfile v3, exact direct semver versions, HTTPS npm registry resolved tarballs and parseable SHA-512 integrity values for each installed package reference. Require `global.json` exact SDK and `rollForward=disable`, enumerate all `src/**` + `tests/**` csproj source declarations with exact NuGet PackageReference versions, and verify original shared full-regression workflow's GitHub actions are SHA-pinned. Record every PostgreSQL service image declaration; **do not silently treat its mutable version tag as OCI digest-pinned**. A deterministic SHA-256 fingerprint binds the exact read source **file bytes**, not a returned package, attested binary, Docker image, dependency vulnerability database or signed SBOM.

One CI step within the **existing** reusable full regression job runs seven offline adversarial tests and the inventory against the real checkout; publish a sanitized JSON report under existing TestResults. Status is only `DECLARED_BUILD_INPUTS_CHECKED_NOT_ATTESTED`; missing/malformed/tampered/float/unsafe declarations fail CI closed with `SOURCE_UNVERIFIABLE`. Report fields `nugetRestoreBytesLocked`, `dependencyVulnerabilityReviewCompleted`, `supplyChainAttested`, `productionReady` and `nationalReleaseAllowed` are permanently false. `containerDigestPinned` remains false until an independently resolved and verified registry digest is explicitly approved and adopted. This sprint does **not** guess Docker manifest digest, retag an image, change runtime dependencies, assert a zero-CVE state, contact registries, invent quality thresholds, or authorize production.
