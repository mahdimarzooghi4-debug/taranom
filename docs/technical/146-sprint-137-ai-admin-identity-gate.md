# TRN-TECH-146 — Sprint 137: .NET AI admin identity evidence boundary

**Scope:** runnable production-language .NET 10 cryptographic identity **evidence verifier**, intentionally not an operational authenticated AI administrator or RBAC implementation. Built into `Taranom.MemberGovernance` and validated by its existing xUnit-v3 test executable in the mandatory inherited 14-job CI. No new NuGet dependency, mock OIDC server or external API is used.

The pure library accepts a **caller-supplied, immutable trusted-configuration object from a future authorized hosting service**, never from untrusted HTTP headers or claims: exact issuer, audience, key-id and RSA public-key PEM. It verifies a bounded compact JWT: canonical base64url, exact `alg=RS256` / `typ=JWT` / `kid` protected header with no embedded key/URL/critical params, RSA SHA256 signature, strict distinct JSON claim names, exact issuer/audience, nonblank subject and token-id and checked `iat`/`nbf`/`exp` times. It does NOT fetch JWKS, perform OIDC discovery, trust a request-supplied public key, introspect accounts, create sessions or log raw tokens. The output stores at most SHA256 of the compact token as a technical diagnostic, not a personally identifying subject.

**Critical governance:** even a valid pinned signature produces `PINNED_SIGNATURE_EVIDENCE_ONLY` and `AdminAuthorized=false`, `RealOperatorAuthenticated=false`, `CommitteeApproved=false`, `ProductionActivationAuthorized=false`. `Decide` denies **every** operation including model inventory, model version registry, training requests, evaluation inspection, committee review, committee approval, production activation and rollback: no actual IdP/role-to-organization binding, accountable committee membership, final approving officer, lawful subject/data scope or nonrepudiation mechanism is currently approved. Signed `role=admin`, `scope=activate` or `productionAllowed=true` claims never change the result. No real issuer, credentials, admin accounts, permissions, policy values, schedules or staff identities are invented or installed.

**Signoff requirements before real admin functionality:** approved issuer/key-rotation/JWKS and audience contracts; per-tenant membership/grants and revocation; session/CSRF and independent human role/review delegation; .NET-admin-to-Python-owned worker communication model without public loopback bypass; authorized operational Postgres persistence, audit/outbox and a fresh source dataset rights gate. Real UI integration will only follow those contracts. Passing a synthetic signed-JWT test cannot be called login or Production readiness. Stage/QA/Release/Production and nationwide release remain DENIED_BY_DEFAULT; PR stays Draft/Open.

**Tests:** genuine freshly generated RSA signatures and checks for correct pinned verification, unknown issuer/audience/kid/pubkey, alg downgrade, embedded JWKS, duplicate JSON fields, malformed tokens, invalid time claims, payload modification, forged admin/committee/production claims and denial across all eight operations. The existing .NET test suite runs these alongside all inherited regressions.
