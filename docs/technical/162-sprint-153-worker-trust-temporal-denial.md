# TRN-TECH-162 — Sprint 153: denial-only temporal and revocation-order claims

## Purpose and fixed boundaries
The preceding synthetic Worker evidence chain checked identity and trust-root claims, then introduced untrusted key rotation/revocation claim order. This sprint exercises attempts to counterfeit **valid-from, expiry and effective/observed revocation timing** using only synthetic assertions. There is **no trusted clock, external timestamp signature, approved TTL, grace interval, Production validity semantics, legal revocation authority, human release authorization or independent custodian**. The source never reads wall-clock time.

## Contract
The public manifest `docs/governance/ai-worker-trust-temporal-template.json` contains `candidate:null`. The new offline `tools/qa/worker_trust_temporal_denial.py` accepts only strictly bounded, test-prefixed synthetic references and exact, strictly parsed UTC timestamps `YYYY-MM-DDTHH:MM:SSZ`. This format, plus the **illustrative** half-open comparison `claimed_not_before <= attempted_at < claimed_expires_at`, are parser test conventions, **not an approved Production clock policy**. The supplied timestamps are *untrusted strings*, not authenticated external records. It requires exact prior denial-only lifecycle context, validates the claimed event graph via the existing Sprint 152 parser and tests claimed observation ordering, effective-time consistency, backdated termination, exact claimed-window coverage, false early-use or expiration, stale/superseded/revoked attempts and cross-transfer/challenge replay.

Even a perfectly consistent future successor or temporal claim yields `TEMPORAL_CLAIMS_REQUIRE_INDEPENDENT_REVIEW`, not `VALID`, `APPROVED`, or `ACTIVE`. Invalid order, missing key windows, expiration, pre-validity, forged approval or timestamp signature, malformed/naive/fractional/unparseable time or fabricated prior authority fails closed. All result flags, including `trusted_clock_verified`, `validity_window_authorized`, `expiration_verified`, `revocation_time_authenticated`, `time_order_attested`, `external_timestamp_signed`, `trust_key_lifecycle_verified`, `custodian_identity_verified`, `human_release_approved`, `production_ready` and `national_release_allowed`, remain literally `false`. No raw claimant strings enter reports.
