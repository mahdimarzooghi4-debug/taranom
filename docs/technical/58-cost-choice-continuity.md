# TRN-TECH-058 — Synthetic cost-choice continuity after an estimate changes

**Recorded:** 2026-10-11. **Base:** Sprint48 PR #55, Draft/Open/Unmerged. **Business:** TRN-BIZ-051 (source-explicit nonbinding five-lane pre-service cost), TRN-BIZ-052 (member's awareness/choice recorded but separate from legal financial commitment and clinical consent), TRN-BIZ-034/035 (emergency guidance never waits for cost and member privacy), TRN-BIZ-048/049/050 (independently valid insurance and official post-service billing). Backlog TRN-EP-09/13/12.

## Existing sources are reused

`SyntheticCostPreviewBuilder` already validates the exact five source-specific components and SHA256 metadata fingerprint; `CostAwarenessRecorder` records append-only nonbinding paper choices, and isolated PostgreSQL `PgSyntheticCostAwarenessJournal` already protects fixture-level durable history. Sprint49 must NOT introduce a parallel consent recorder, wallet, final invoice, insurer source, actual member or database. The missing capability is an explicit **read-only comparison** of a pinned past choice and a potentially changed estimate so prior member choices cannot silently apply to an unrelated/newly revised estimate.

## Decision contract

New INTERNAL pure `SyntheticCostChoiceContinuity.Inspect` receives caller-supplied **synthetic** previous/current `SyntheticCostPreview` values and the previous `CostAwarenessSnapshot`. Before reading any previous choice: *rebuild BOTH previews* using the canonical existing builder; verify every five-component value, source, state, ID, revision, and supplied fingerprint; ensure identical member, then verify the pinned historical choice owner, preview ID/revision/fingerprint and **replay all previous commands with the existing CostAwarenessRecorder**, including exact history revisions. A changed/mismatched/fabricated preview or historical owner fails closed.

When structural inputs are valid, compare all five lanes on exact record equality. Amount, source ref/revision, evidence UUID, missing/provisional/conflicted state or altered preview ID/revision can change the result. The read surfaces the typed changed components and previous **unverified** latest choice. Even equal lines under a *new* PreviewId or revision require a **separate future authorized review**. A changed preview with missing insurer value does NOT imply zero; conflicting source never produces a numeric quote. Distinct statuses identify no previous choice, same exact unverified preview, changed preview, current missing components and current conflicting components. None is authorized acceptance, a rule for legally mandatory re-notification, price/insurance accuracy, payment/credit hold, final liability, provider clinical consent, treatment/triage or member account mutation. The `ChoiceCarriedForward`, `FinancialCommitmentCreated` and `ClinicalConsentCreated` fields are always false. No new timeframes, signatures, automatic member notices or thresholds are invented.

## UI and tests

Extend existing Persian RTL `/member/costs` with four clear informational distinctions: the exact cost preview version and five untrusted sources, previously unverified awareness/choice, necessity of separate review if scope/value/source or uncertainty changes, and independent legally valid provider medical consent / financial obligations. All data unavailable, no autofill, choice/action controls disabled and emergency reminder unconditional. Four real built Chromium regressions for no reuse, no payment/clinical authorization, sponsor privacy, history/no private network or storage. Adversarial xUnit for all five components, changed source without amount change, version and preview ID, unknown/zero, conflicts, stale history, cross-member, tampered fingerprints, no authority. Preserve 12 pinned CI jobs including actual isolated PostgreSQL and national/AI deny-only policies.
