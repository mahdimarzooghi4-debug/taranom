# TRN-TECH-077 — Strict loopback HTTP authority and real concurrent journal admission

**Date:** 2026-10-11. **Parent:** Sprint67 PR #75, exact head \`1297828216d7cd7fa25b3a83648464c68058a753\`, Push/PR 14/14 successful, Code Review preliminary COMMENTED.

## Concrete security defect, not new invented product features

The existing nondeployable localhost-only ASP.NET host accepted an arbitrary HTTP \`Host\` header, although listening on loopback does **not** defend an origin from hostile DNS rebinding. It also had a wildcard \`MapFallbackToFile("index.html")\` that served the center UI for unknown paths (including ones resembling real private APIs). Neither behavior proves an authentication breach, but both must be corrected **before** a future genuine member, clinician or insurer integration. This package strengthens the existing technical execution seam and stress-tests existing transactional journals, rather than adding an additional synthetic product module.

## Exact behavior and implementation

- Enforce both host and port **at request entry**, before static file or read/write route handling: only \`127.0.0.1:4320\` or \`localhost:4320\` are acceptable to this test-only host. A request with a different, missing, incorrect-port or rebinding Host receives HTTP **403** with \`UNTRUSTED_LOOPBACK_AUTHORITY\` and explicit \`syntheticOnly=true\`, \`memberAuthenticated=false\`, \`managerAuthenticated=false\`, \`clinicalReviewCompleted=false\`, \`nationalReleaseAllowed=false\`. No member, clinical or tenant data is returned. Do **not** interpret host validation as identity, authenticated session, cryptographic proof, clinical consent or role grant.
- There is **no approved reverse proxy**. Deny \`Forwarded\`, \`X-Forwarded-Host\`, \`X-Forwarded-Proto\`, and \`X-Forwarded-For\` instead of silently trusting them. The same denial covers center/member page entries and all test-only JSON GET/POST routes. Retain no-store, nosniff, frame DENY, referrer no-referrer and existing restrictive CSP; no CORS grant or credentialed browser session.
- Replace the wildcard SPA HTML fallback with fail-closed **404**: \`/member\`, \`/login\`, \`/api/v1/health-records\`, \`/center/administrator\`, unknown \`/member-demo/\` routes and unrecognized \`/internal/\` routes must never turn into a valid demo page. Exactly the existing center root (static \`/\`) and separately mapped member \`/member-demo/\` remain served with distinct HTML entrypoints. Existing approved test-only commands and static bundle assets work as before. Do not add or infer real APIs.
- Add genuine independent-process Python HTTP attack checks: hostile Host against HTML and both center/member test data; injected forwarded authority, cache/security headers, unknown-route denial, no accidental HTML leak and preservation of ordinary 200 local-only pages. Add three **actual PostgreSQL HTTP race trials**: two distinct center commands with same expected revision must yield one accepted/one stale and one DB event; two distinct member-support initial requests must yield one accepted/one stale; two simultaneous identical support request IDs must yield one accepted plus one Replay, and a single durable revision. This verifies previously assumed multi-worker concurrency behavior using the existing canonical journals, not an alternative domain model.
- Add Playwright Chromium/API regressions to the existing member browser suite for hostile Host, forwarded authority, unknown-path denial and correct distinct center/member entrypoints. Keep all 10 original center UI tests and 7 member UI tests; add 3 member browser/API tests. Retain full inherited 14 independent jobs (test-only PostgreSQL 18.6, .NET 10, React/TS, both real Chromium apps, public Git history/AI bans and national DENIED checks), exact-head Push and PR green.
