## Functional gap

The center management workspace already supports creating multiple test departments, recording synthetic unverified doctor affiliations, assignments and ending affiliations. The immutable PostgreSQL event/audit journal and independent historical replay are functional. But a department operator cannot request a *single department-scoped, version-pinned roster* and see which synthetic doctors were associated at a past version versus now. Do not invent external identities, national licence registries, a parent network, a new writer, or approval flows.

### Bounded new GET read model

`GET /internal/demo/v1/centers/{centerRef}/departments/{departmentRef}/roster?expectedCurrentVersion=N&asOfVersion=M`

Enabled only inside the pre-existing `TARANOM_CENTER_DEMO_TEST_ONLY=CI_EPHEMERAL_ONLY` ASP.NET localhost:4320 host backed by the fixed isolated PostgreSQL database. Both refs must satisfy the original bounded `test:` grammar; exactly two unique query fields, unsigned strict ASCII decimal with no leading zeros (except 0); requested history `0 <= M <= N`. Read the **existing canonical** `PgClinicalCenterJournal.ReadAsync`, which rehydrates and checks persisted relational projections, immutable events and linked audits under PostgreSQL row locking. Reject a stale expected current version with 409; reject malformed/ref/path/query with 400 and missing department in specified historical prefix with 404. Build as-of version **only by replaying accepted event commands through the pre-existing pure center reducer**, checking every applied event/version; no parallel domain logic. Only return test-only doctor refs with `PendingIndependentVerification` affiliation **assigned to the requested department as of M**, sorted deterministically. Ending affiliation removes doctor from the current department roster but does not erase earlier history. Re-read current journal version immediately before returning, reject observable concurrent changes (not a durable snapshot across independent calls).

Every positive/negative response includes `syntheticOnly=true`, `managerAuthenticated=false`, `professionalQualificationVerified=false`, `clinicalAccessGranted=false`, `providerContractVerified=false`, `billingAllowed=false`, `nationalReleaseAllowed=false`. For doctor rows, `licensureVerified=false`, `clinicalPrivilegesGranted=false`, `assignmentUnverified=true`. No person names, real national IDs, health data, facility/medical licence or contract. Do not claim that knowing a center `test:` ref is authentication or a production tenant permission; this is an isolated demo.
