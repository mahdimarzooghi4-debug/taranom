# TRN-TECH-022 — Human review note recording bound to unverified evidence

**Date:** 2026-10-10. **Status:** synthetic-only, internally testable foundation; no human reviewer authority or clinical/legal decision approved.

Business inputs: TRN-BIZ-053/054 (one multi-department clinical center, center-managed doctor affiliation) and TRN-BIZ-043/044 (independent medical credentials and valid contracts). Technical lineage: TRN-TECH-018 evidence-intake, TRN-TECH-019 transactional evidence journal, TRN-TECH-020 queue and TRN-TECH-021 frozen snapshots. All stacked PRs are Draft/Open; none is in main.

## Human-review scope, deliberately not final decision policy

Current product decisions do NOT identify an authoritative organization for professional credential checks, actual independent review authority, allowed reviewer status/result taxonomy, legal approval criteria, source provenance, appeal/finality, retention or production-grade identity. This Sprint **does not** fabricate any of them. The only result possible is `PendingSourceVerificationRecorded`: a human-review *note submission claim* exists but professional verification still awaits an independent authoritative source.

The internal/test-only `PgHumanReviewNoteJournal` records an immutable, versioned sequence of annotations with `ReviewerClaimRef` and `RationaleEvidenceRef` as **synthetic opaque references**. These fields are *not* a verified person, a signed decision or free text from actual patients/doctors. No outcome can confirm or reject credentials, activate a provider, change clinical access, wallet, insurance, fund or payment.

Every submission pins: one center, one exact physician/representative subject type, **one evidence event revision**, a frozen snapshot UUID + exact element index, a caller-supplied reviewer marker, a rationale reference, request UUID and expected note revision. The existing validated `PgFrozenUnverifiedReviewQueue.PageAsync` checks the immutable captured record and its digest; the recorded center, subject, type and evidence revision must equal the selected element. Missing, mismatched or corrupted snapshot **never falls back to live queue data**.

The PostgreSQL test-only tables are `internal_test_human_note_head` (one revision-locked row for a source review event, with composite FK back to that exact accepted evidence event), `internal_test_human_note` (immutable note payload, one request-idempotency key per source evidence), and `internal_test_human_note_audit` (same-transaction accepted note audit). `SELECT FOR UPDATE` serializes expected revisions; complete note history replay rechecks note digest, audit, request, sequential revisions and scope. An accepted note + audit + head CAS happen in ONE transaction; injection of audit failure rolls everything back. Exact retries replay without a duplicate; changed retries conflict; stale revisions cannot rewrite history. Ordinary DELETE/UPDATE against accepted notes/audit are rejected by triggers. SQL superusers can still bypass DML guards and SHA-256 is a consistency check, not a signature.

No public API, frontend form, authenticated reviewer, medical practice or provider credential integration is connected. The predecessor Sprint08 private-data interlock remains DENY-ONLY. This component is not permissioning, review assignment, appeal, or a clinical decision ledger. Negative results are returned to internal code but **no complete rejected-attempt audit is claimed**; production rejection telemetry must be independently specified.

## Scope of tests and nonclaims

18 genuine PostgreSQL cases cover audit-recorded annotation, repeated/conflicting requests, version race and concurrent exact retry, preserved note history and change-of-rationale, cross-center and cross-subject snapshot mismatch, exact evidence version, malformed reviewer/rationale, manager-vs-doctor separation, missing snapshots, accepted audit rollback, append-only write protection and deliberately tampered revision fail-closed. Preserve 59 prior review journal/queue/frozen-snapshot tests and all twelve independent CI regression jobs.

Important limitations: snapshot and note are **synthetic test data**, reviewer marker is not identity. A frozen snapshot can be generated by a test SQL principal; there is no issuance authentication, signed decision, human approval, production retention, secure evidence storage or external legal attestation. The full-history replay is unbenchmarked for real scale. Clinical/contract criteria and final decisions require explicit Business authority and independent human/legal/medical review before coding any approval operation.

**No Ready/Merge/Stage/formal QA/Release/Production without explicit approval.**
