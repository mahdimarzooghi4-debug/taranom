## Contract

The two existing, separate canonical append-only test-only PostgreSQL journals are authoritative only for their **internal synthetic events**: `PgSyntheticCostAwarenessJournal` (pre-treatment estimate, unverified choice) and `PgSyntheticSupportJournal` (unverified two-topic support intake and follow-ups). No new schema or parallel reducer. Add one GET-only read adapter, available only when the already approved `TARANOM_CENTER_DEMO_TEST_ONLY=CI_EPHEMERAL_ONLY` and `TARANOM_COST_JOURNAL_DEMO=CI_EPHEMERAL_ONLY` guards both hold:

`GET /internal/demo/v1/cost-previews/{previewId}/support-link/{caseRef}`.

It accepts only lower-case canonical nonzero UUID, a `test:` support case ref and **no query fields**. Exact Host/port and no forwarded headers enforced by existing Kestrel middleware. It fully reattests the two independent PostgreSQL journals through their existing canonical read/replay checks, not a UI-provided claim. The original support event must be topic `InsuranceCoverageDispute`, same synthetic member as cost preview, and literal evidence reference `test:cost-preview:<canonical-uuid>`. It returns 404 for a missing cost or support record; 409 for wrong topic/member/source; 400 for bad refs; 503 for tampered/unverifiable journal; it never leaks member scope, claim evidence, private amounts or fingerprint on a denied cross-reference. After reading both, re-read the same revisions and cost fingerprint to catch observable concurrent changes; **cross-journal atomicity is explicitly FALSE**, not invented. Output identifies observed independent revisions, the bounded `test:` reference and follow-up count only; no total, coverage, insurer answer or liability.

## Actual manual flow

In the existing isolated Member cost demonstration, a tester manually registers a five-source synthetic cost preview in the existing PostgreSQL journal and optionally records an unverified cost choice. The separate **explicit** UI action checks that a user-selected `test:` support case is still empty, then issues one `SUBMIT_UNVERIFIED` action to the **existing** support POST endpoint, with topic `INSURANCE_COVERAGE_DISPUTE` and `unverifiedEvidenceRef=test:cost-preview:<UUID>`. The command is pinned by a new UUID and persisted using the existing support journal's idempotency/revision lock. If the HTTP ACK is lost *after commit*, the UI freezes the same command and allows only the exact UUID retry. The link inspection itself is a different manual GET and writes nothing. Reload has no implicit POST, browser storage or session; tester manually supplies preview UUID and case ref and asks to reattest both real DB journals.
