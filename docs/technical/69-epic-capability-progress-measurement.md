## Versioned candidate decomposition and metric definitions

- \`docs/governance/epic-capability-progress-draft.json\` is an **UNAPPROVED** proposed decomposition: exactly **3 preliminary acceptance questions per Epic × 13 Epics = 39 candidate capability slots**. It is NOT an assertion that every Epic needs precisely three eventual implementation tasks or that each is equally weighted. Human Product/Business/Technical owners must refine and ratify the real acceptance contracts and relative sizes before claiming a product-wide completion percentage.
- Each candidate capability includes a provenance link to its Epic's accepted TRN-BIZ policy refs; an optional **existing** implementation-file + test-file pair; and a strictly bounded evidence class \`SYNTHETIC_INTERNAL\`, \`DISCONNECTED_UI_ONLY\`, \`OFFLINE_POLICY_ONLY\` or \`NO_EVIDENCE\`. These file pairs verify only **that referenced local source files exist**. They do NOT assert test execution, correct real behavior, connected Production readiness, clinical authorization, member rights, feature acceptance, or approval. Green CI elsewhere may show synthetic regression is healthy, never that every named capability is delivered.
- \`formal_acceptance_observed=false\` must hold for every provisional capability; weights stay \`NOT_APPROVED\`, baseline stays \`DRAFT_UNAPPROVED\`. The validator **fails closed** if someone invents acceptance/percent fields, drops an Epic/market, shrinks/duplicates a candidate slot, supplies missing/out-of-tree/symlinked evidence paths, claims a real production state from synthetic code, or changes the 17-dimensional national DENIED inventory.
- The output distinguishes: \`epic_count=13\`; \`provisional_capabilities=39\`; count of linked existing **non-Production code/test file pairs**; count of candidate capabilities with **no evidence link**; \`formally_accepted_capabilities_recorded=0\` inside this public candidate registry; and all 17 external blockers. \`overall_implementation_completion_pct=null\`, \`formal_acceptance_pct=null\`, and individual \`implementation_completion_pct=null\` until independently ratified acceptance scope and actual accepted evidence exist. There is **no invented 0% implementation**, equally weighted averaging, artificial 20% retention, or conflation of a file link with feature Done.
- For each Epic the report exposes only title, provisional count, technical *reference links* count and exact missing external-blocker categories already defined by the source inventory. All four national/market dimensions must remain present and blocked even though they are not individually counted as Epics.
- A future measured percentage must be derived **only after** owner-approved acceptance inventory/weights or an explicitly approved unweighted method; each accepted capability must have correct exact-code lineage, passing applicable functional/integration/security and real Stage/QA tests, independent human review, required real external authority/consent and an explicit acceptance decision. Production release itself remains a separate gate even after all implementation checks pass. No AI or LLM may approve its own work.
