# TRN-TECH-154 — Sprint 145: test-only persistent, independently checked Worker event evidence

This is a **non-operational synthetic evidence exercise**, stacked over Sprint 144, not the regulated AI audit store and not a Production design decision. The existing bounded .NET→Python CI-only Worker retains its read-only inventory action and all authority flags false.

## Execution
The disposable Kestrel host opts into a local file only when `TARANOM_AI_WORKER_EVIDENCE_TEST_ONLY=CI_EPHEMERAL_ONLY` and an absolute fixture pathname `/tmp/taranom-worker-*/worker-evidence.jsonl` is given. The host appends a `Boot` entry with its fresh process epoch at initialization, then records a fixed enum `Success`, `ProcessRejected`, `InvalidReply`, `DeadlineExceeded`, `RequestCancelled`, `Unavailable`, or `CapacityDenied` on actual Worker admissions/completions. The evidence never stores request or tenant identifiers, medical/financial records, tokens, stderr, raw Worker responses, mutable model artifacts or operator-provided free text. No extra HTTP evidence route exists. A failed write/verification overrides a would-be successful Worker HTTP response with an existing generic 503.

Every record carries sequence, process epoch, fixed outcome kind, previous SHA-256 and current SHA-256 calculated over a canonical v1 deterministic framing; C# strictly validates the *entire* prior file before any new append, disallows path symlinks, accepts no malformed UTF-8/JSON, wrong sequence, unknown field/outcome, truncation, wrong epoch or broken hash link, and flushes the append to disk. Per-process locking and exclusive file acquisition serialize concurrent writes. Bounds: at most 4096 records and 512 KiB in a test fixture. No partial-entry repair or silent reset; broken history must fail closed.

## Evidence and adversarial tests
An independent C# probe executes 100 parallel writes, reopens a stored chain, adds a second epoch, detects altered contents/invalid tail and denies a stale epoch or non-isolated path. In the existing 14-job CI, the real Kestrel test harness persists only the bounded hash chain, actually restarts the process as in Sprint 144, verifies that old process-local counters reset but the *test-only file* persists and contains two epochs, performs an actual HMAC-verified read-only Worker call after restart, and runs an independent Python SHA-256/UTF-8/canonical-record verifier over the saved file. No real OIDC, consent, patient identity, external model API or Production inference is accessed; existing tests and recovery rehearsal remain intact.

## Limits and policy
**Hash linkage does not prove authenticity** if the filesystem owner can delete/rewrite the entire file and recompute the public SHA-256 chain. Local fsync does not confer immutability, legal audit, external custody, multi-replica consistency, external monitoring, SLA or approved disaster-recovery objectives. The log can also lose an unflushed event in a process/OS failure, and cannot prove completeness against deliberate truncation. Do not treat it as official audit or Production Operational Readiness. Actual external immutable retention, human committee review, approved model and first-party data, service-to-service identity, scope revocation and explicit human Production promotion remain OPEN. Keep all stacked PRs Draft/Open/Unmerged; no Merge, Ready for Review, Stage, QA Gate, Release, Production or national activation. `DENIED_BY_DEFAULT` remains.
