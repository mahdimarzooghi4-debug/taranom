# TRN-TECH-160 — Sprint 151: nonauthorizing custodian identity/trust boundary

## Scope and business trust boundary
The fully green Sprint 150 contract can structurally check a synthetic two-epoch Worker ZIP and untrusted alleged outside receipt, but cannot prove *who* received it or whether an organization, signing key, administrator, reviewer or challenge was genuine. Sprint 151 makes this explicit with a **strictly synthetic, denial-only trust-claim evaluator**, independent of any Production identity or external model route. It is stacked over Draft PR #164; no merge, human approval, Stage, QA Gate, Release or Production admission.

The public template `docs/governance/ai-worker-custodian-identity-template.json` has `candidate:null`. The evaluator `tools/qa/worker_custodian_identity_boundary.py` accepts only bounded, canonical-shaped, test-prefixed *untrusted assertions*: custodian ref, administrative domain ref, alleged trust-key ref, alleged reviewer ref, transfer ref, challenge ref and `claimed_status=PRESENTED`. Fixed comparison tokens are **not actual identities, accepted trust anchors, real key fingerprints, nonces, verified reviewers or replay protections**; they exist only to exercise negative control-flow. The tool accepts an independently computed synthetic Worker receipt evaluator *context* only when the canonical archive was structurally checked and all earlier authority fields remain false. Neither a matched synthetic claim nor a fabricated positive receipt report can turn any identity, trust root, administrative separation, receipt, review or Production flag true.

A template with `candidate:null` yields `EXTERNAL_CUSTODIAN_IDENTITY_NOT_CONFIGURED`. Even complete matching claims with a *structurally matching but unauthenticated* receipt yield `IDENTITY_CLAIMS_REQUIRE_INDEPENDENT_REVIEW`. Without any alleged external receipt, even matching claims yield `DENIED_NO_AUTHENTICATED_OUTSIDE_RECEIPT`. Cross-transfer replay, reused challenge, changed alleged admin domain/key ref, unsafe personal/URI/key identifiers, fabricated signature or release approvals, extra fields, duplicate JSON, unsupported version or scope, forged prior authority or missing structurally checked archive all fail closed. Denial reports contain **no claimant references**, all custodian/receipt/release flags false, and are created once with owner-private 0600 permissions.

The canonical 14-job reusable CI retains the real .NET→Python synthetic inventory bridge, persistent evidence chain, real process restart, independent HMAC checkpoint, separate Linux unprivileged verifier user, bounded offline ZIP receiver and PostgreSQL/Chromium/recovery gates. After the actual two-epoch synthetic ZIP is produced, a separate Python process reads **only the two empty committed templates** and rechecks that no outside identity or receipt exists. The strict production gates and national `DENIED_BY_DEFAULT` are unchanged.
