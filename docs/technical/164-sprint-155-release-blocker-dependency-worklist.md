# TRN-TECH-164 — Sprint 155: product-wide release dependency worklist

## Reason for selecting this work package
After Sprint 154, seven consecutive AI Worker synthetic authenticity/custody Sprints had added only denial exercises, while external legal, identity, clinical, financial and Production prerequisites remain unresolved. The approved Business baseline demands the **complete** first nationwide release across 13 Epics and three markets; continuing to build pretend external AI provider identities, trust roots or signatures would not advance real deployment. The current repo already has an offline 39-slot candidate Epic catalogue (TRN-TECH-069) and a strict 17-domain national blocker register (TRN-TECH-045). Instead of another hypothetical positive handshake, Sprint 155 **reuses and cross-links those two existing validators** and produces one actual engineering/human decision *handoff list*.

## Backend/contract and security
The new `tools/policy_checks/build_release_dependency_worklist.py` is an offline read-only, source-backed compiler. It explicitly calls canonical `check_epic_capability_progress.inspect` and `check_national_launch_blockers.audit_inventory`; both must accept their original **unapproved and fully blocked** scope. Exactly 13 Epic, 39 nonapproved candidate capability slots, 17 launch obligations (13 Epics + three markets + national coverage), and all 18 pre-existing external evidence/decision categories are required; none can disappear by changing a denominator. It derives each requirement's affected domains, related accepted TRN-BIZ references and counts of *non-production* code/test pairs linked to its affected Epics. No invented owner, relative priority, readiness percent, cost, threshold, test gate, deployment location or partner is produced.

Outputs are source-fingerprinted JSON plus concise offline Persian Markdown and CSV with only allowlisted source IDs. Every row is `BLOCKED_UNVERIFIED`, decision owner `NOT_ASSIGNED`, formal acceptance false; globally `formal_approval_observed=false`, `production_ready=false`, `national_release_allowed=false`, `release_admission=DENIED_BY_DEFAULT`. Changed sources, missing market/domain/capability, fake approval, missing referenced code/tests, symlinked sources, duplicates or invalid policies yield only a redacted empty `DENIED_UNVERIFIABLE_DEPENDENCY_SOURCES` report and nonzero CLI exit. New report paths refuse overwrite/symlink. A list of candidate code/test links does **not** mean those capabilities are feature-complete.

The original canonical 14-job full regression is unchanged in job count and external security gates; the existing internal-contract job now also runs negative mutation tests plus the real source-backed compiler and checks 17/18/39, all false approval and Denied. The existing /operations/progress view and offline Epic console retain ownership of capability progress. This is an **additive action/dependency handoff**, not a competing percentage dashboard.
