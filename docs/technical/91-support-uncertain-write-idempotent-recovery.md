## Concrete user-journey reliability defect
Previously the test-only browser generated a fresh `requestId` for every click. If a POST committed in PostgreSQL and its HTTP response was lost, the browser discarded the original command, making an attempted fresh submission ambiguous or duplicative. Existing backend implements **exact request idempotency** under actual PostgreSQL transactions (repeated exact request → `Replayed`; modified payload with same ID → 409), but the interactive test UI never reuses it.
