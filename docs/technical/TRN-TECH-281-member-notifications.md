# Member support notifications

Figma frame 104:2 supplies notification card order, typography, colors, header/back control, unread marker and home-active navigation. `/patient-app/notifications` now reads real owner-scoped notifications. Account and existing preview navigation open the connected route. All static assets are local; existing exact logo/nav assets are reused, with downloaded 8×8 unread and 24×24 active-home SVGs. Pagination, timestamps, read controls, counts and recovery are functional additions to the static design.

Scope is intentionally support answers only. A successful staff reply inserts one durable notification in the same PostgreSQL transaction as the answer and command receipt. Unique request_ref prevents duplicate notifications on retries. API startup backfills pre-existing answered tickets once per missing source under the existing schema bootstrap lock. Notification ownership is derived by joining the persisted source request's issuer/subject; no client owner selector is authoritative. The generic feed does not include the patient's request/answer content, a fabricated clinical event or membership/payment activity.

GET `/api/v1/me/notifications?before=&notificationRef=` returns up to 20 items, a server sequence cursor, and the global unread count from one repeatable-read snapshot. Exact lookup is available for uncertain-write reconciliation. POST `/api/v1/me/notifications/{ref}/read` is a monotonic acknowledgement: COALESCE preserves the first read timestamp on concurrent/repeated requests. Unknown and other-owner resources return 404. Both endpoints require authenticated host identity and use no-store.

Reads never acknowledge automatically. The user explicitly selects "خواندم". The UI confirms valid receipts, reloads server state, and reconciles lost responses by an exact GET without repeating POST. Denied refreshes clear prior items. The response link opens `/patient-app/support?requestId=...`; the support history uses the exact owner-scoped intake request ID, rather than showing unrelated tickets. A notification is not an external push, SMS or email, and does not enable notifications elsewhere or add an unread badge without data.

Verification: PostgreSQL HTTP tests cover anonymous and cross-owner denial, one notification per answer/replay, concurrent read timestamp stability, omission of private answer content, bounded nonoverlapping pages/global counts, and backfill after restart. Browser tests cover read persistence/reload, lost response, precise support target, denied refresh, missing session, malformed/unsupported records, pagination, empty state and 390px local asset geometry. Existing profile/support/appointment tests continue to run. APK creation/download is deferred per the user's instruction; no deployment or merge occurs.
