## Integration dependency actually addressed
A selected and independently authorized prospective healthcare-system partner may support HL7 FHIR metadata. Before planning its adapter or claiming official nationwide connectivity, the operator can privately verify that its advertised server capability statement is structurally parseable, what version is **claimed**, and what standard resource/interaction names are **advertised**, without accessing any patient, insurance claim, clinician or subscription. No partner name, server or user identity is selected/invented here.

HL7 FHIR R4 REST defines the anonymous read-only capabilities interaction `GET [base]/metadata`; `CapabilityStatement.fhirVersion` identifies the advertised standard version. The tool deliberately uses only metadata and **never** assumes advertised capabilities imply authorized access, valid contracts or real supported resources. References: [HL7 FHIR HTTP API](https://hl7.org/fhir/R4/http.html), [CapabilityStatement](https://hl7.org/fhir/R4/capabilitystatement.html).

## Bound source and runtime contract
- New stdlib-only `tools/policy_checks/check_private_fhir_capability.py`. No supplied target → `TARGET_NOT_CONFIGURED`, offline, no DNS/network, all member/clinical/legal/national rights false. Public CI executes exclusively this no-target path and mocked hostile transport cases.
- Optional **operator-controlled real probe** requires an existing 0600 owner-private JSON target file **outside Public Git**, a distinct new-only owner-private 0600 output in 0700 directory, and **explicit** `--acknowledge-authorized-technical-probe`; omission denies without network. An operator must independently establish lawful right to perform this anonymous technical read; the flag is not proof of lawfulness. Input schema has only `schema_version=1`, `scope=PRIVATE_AUTHORIZED_FHIR_CAPABILITY_TARGET`, a DNS **hostname** and an exact base path comprised solely of bounded safe ASCII route segments. No patient IDs, endpoint query, FHIR search, dynamic custom URL, arbitrary port or credentials.
- Reuse existing trusted hostname validator and DNS **all-addresses-public** guard; single pinned numeric IP 443 connection, verified CA/SNI/TLS 1.2+, peer-IP match and certificate expiry, exactly one `GET <base_path>/metadata`. Fixed `Host`, `Accept: application/fhir+json`, `Connection: close`, no cookies, tokens, redirect, retry, search or additional transport connection. Timeout, 32-KiB total response headers, 256-KiB JSON body, no response compression, fixed content types; reject HTTP !=200. No POST, no read of Patient/Claim/etc records.
- JSON is untrusted: duplicate-key/NaN/malformed/big responses fail closed; exact `CapabilityStatement` resourceType, recognized status/kind, bounded syntactically valid `fhirVersion`, one or more `rest.mode=server` blocks with properly typed `rest.resource[].type` and advertised standard `interaction[].code`. Return only standard public FHIR resource/interactions from a fixed low-risk allowlist; **do not** publish vendor metadata, URLs, host/IP, opaque references, sample patient IDs or response bytes. Other supported resources may exist and are not denied merely because not in the allowlist.
- A positive outcome is **`FHIR_CAPABILITY_SYNTAX_OBSERVED_NOT_AUTHORIZED`**. It is not a successful interoperability QA, version compatibility decision, network/partner qualification, approved data mapping, clinical consent, provider payment permission or legal exchange. Real integration must later receive signed contract, endpoint topology, selected version, patient-rights and consent contract, real security design, and human/medical/legal approvals.
- Tests use actual stdlib HTTP framing over mocked TLS + negative SSRF/redirect/Host/path, malformed metadata/duplicate keys, wrong MIME, excessive headers/body, missing FHIR fields, private file checks and a no-network CI default. All inherited 14 CI jobs incl real local PostgreSQL and Chromium remain mandatory on exact Push+PR SHA. CI dispatcher strictly named/local/no-input/no-secret read-only.
