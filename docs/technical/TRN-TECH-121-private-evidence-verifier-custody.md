## Material, verified implementation problem

The shared `check_private_external_evidence.py` already hashes real privately held files safely by anchored descriptors and denies public repository inputs, but its standalone CLI used `Path.write_text` for the report: it could overwrite existing reports/symlinks and produce group/world-readable private output according to filesystem defaults. Also private manifests read by direct CLI were not required to be owned by operator, single-linked and owner-only (0600). These failures could compromise confidentiality or evidence history even without granting release. The neighboring batch/reconciliation tools already required stronger private controls. Do **not** contact real partners, read actual confidential files in public CI, or silently repair any existing private report.

## Non-Production operational safety upgrade

1. Preserve the canonical `inspect` semantics: exact current 17 mandatory release dimensions, actual SHA-256 matching, 200-entry bound and no approving artifact status. On private manifest paths outside public root, require regular single-linked owner-owned mode 0600 (or stricter), reject all symlink parents and aliases, and maintain descriptor inode/mtime guard. Public empty-template `docs/governance/external-evidence-intake-template.json` remains compatible for existing CI with no real evidence.
2. For direct CLI with any external private manifest, reject public, alias, symlink or group/world accessible report parent **before reading private evidence**, require parent directory owner-owned and 0700 (or stricter); never create parents implicitly in private mode. Output is new-only 0600 via `O_CREAT|O_EXCL|O_NOFOLLOW` relative to pinned directory FD; verify created file's inode/regular type, fsync output and parent, re-check the pinned parent/name. On write/fsync error clean up only the exact new inode, never overwrite or delete an older report or follow a symlink. Emit only fixed denial codes; no filenames, root paths, SHA256, custodian refs or file bytes.
3. Existing public empty-template CI path remains limited to `EMPTY_TEMPLATE_NO_EVIDENCE`; use 0600 and exclusive new-only file creation instead of write_text, and reject private/real data under the public checkout. This is not a confidential report format and not a Stage/Release decision.
4. End-to-end regression uses new real POSIX filesystem tests with actual private dummy artifact bytes (never real partner evidence): private 0600 manifest/report, world-readable and hard-linked manifests, symlink ancestors, report symlink/existing target/no-clobber, group-visible destination, public-tree alias, injected fsync failure cleanup, original valid CLI and public empty template. Original byte hashing and comprehensive `build_private_evidence_batch` / `compare_private_evidence_snapshots` tests remain unchanged.
