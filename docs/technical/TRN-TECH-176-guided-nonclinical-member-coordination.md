# TRN-TECH-176 — DRAFT / source-guided unverified member coordination workbench

Date: 2026-10-18 | Parent: Sprint 166 Draft PR #180. Technical scope, not legal, clinical or operations approval.

## Existing approved constraints
TRN-BIZ-046/047 reserve medical decisions and clinical referrals for licensed providers, and assign Taranom a strictly nonclinical experience-coordination role. Existing TRN-TECH-040/115 and the canonical case/reducer are already implemented: append-only `RequestNonclinicalCoordination`, `RecordUnverifiedCoordinatorContact` and `AttachUnverifiedClinicalSourceReference` with PostgreSQL immutable paired audits, UUID replay and revision CAS. The real member/doctor identity, consent, provider communication, clinical record, emergency handoff and appointment sources are explicitly absent.

## New bounded user-facing capability
Provide an explicit Persian guided workbench on the existing `/member-demo/coordination` page. Compute the next *suggested* step exclusively from the full currently valid single-case PostgreSQL event history: no history = require an explicit GET; revision zero = offer initial request; after a root request and without any contact claim = suggest adding an unverified coordinator-contact claim; if a contact claim exists but no clinical-source reference claim = suggest adding that opaque reference; when both event kinds exist, display observed counts and no further suggested action. Contacts and source claims have NO enforced clinical order or real completion definition: if the reference claim precedes contact, suggest the absent contact; existing manual buttons remain available and are never converted into medical authorizations.

Every suggested write requires an independent human click and uses the existing `issue(action)` function, fresh UUID, source-derived scope and current revision, backed by the existing PostgreSQL writer. No composite auto-POST, external partner, notification, new business rule or separate source. The guide must not show an actionable next step while a request is in flight or an ACK is unknown, even if the event committed. Existing explicit manual exact-UUID replay or read-only source match (Sprint 162) remain the only recovery actions. All existing denial flags and warning about emergency services persist.
