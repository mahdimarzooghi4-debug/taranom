## Concrete product-integrity problem

The existing Center React demo exposed *two separate* historical reads: `/history` to inspect accepted transitions and `/versions/{n}` to inspect the historical center state. Each independently reattests current PostgreSQL state but has no required `expectedCurrentVersion` parameter. Between reads or between history pages, another accepted event can change the actual center revision. The operator may observe a valid historical snapshot and a valid timeline from **different source versions**, incorrectly treating them as a single auditable picture. Sprint93/94 introduced stricter per-doctor and per-department readers; the **overall center history** still lacks a combined version-pinned read.

## One bounded source-consistent read (non-breaking)

Introduce test-only `GET /internal/demo/v1/centers/{centerRef}/audit-workspace?expectedCurrentVersion=N&asOfVersion=M&afterVersion=K&limit=L`, with `0 <= K <= M <= N` and `1 <= L <= 20`. The same existing localhost:4320 `TARANOM_CENTER_DEMO_TEST_ONLY=CI_EPHEMERAL_ONLY` fixed isolated PostgreSQL guard, strict Host/forwarded authority and no CORS remain mandatory. Only the existing original bounded `test:` center grammar is valid; exactly four unique canonical nonnegative ASCII integers with no leading zeros. Missing/excess/duplicate fields, invalid current/as-of/cursor/limit, real refs denied 400; changed source revision 409; inability to reattest source or replay 503.

On each request, call only the canonical `PgClinicalCenterJournal.ReadAsync`, which already attests accepted event digest, append-only paired audit and relational projection. Require exact expected current version. Replay **the same accepted event commands** using the unchanged pure `ClinicalCenterJournal.Apply` to the requested historical version M, checking each applied event and version. Generate BOTH `SnapshotDto.From(past)` and bounded original chronological event page from that one checked historical `CenterSnapshot`. Re-read original center journal only to deny obvious concurrent advancement before response. `sameSourceSnapshot=true` means both returned objects came from **one** reattested state. It explicitly does NOT mean a durable snapshot across HTTP pages; `durableCrossRequestSnapshot=false`. Subsequent pages must repeat exact expected current revision, and any accepted concurrent center change fails 409. The older `/history` and `/versions` endpoints remain unchanged for compatibility but should not be combined to claim pinned coherence.

No new schema, journaling path, background job or parallel domain decision algorithm. Denial responses omit source refs, event data and snapshot. All positive/negative replies permanently say `syntheticOnly=true`, `managerAuthenticated=false`, `professionalQualificationVerified=false`, `clinicalAccessGranted=false`, `providerContractVerified=false`, `billingAllowed=false`, `nationalReleaseAllowed=false`; historical event labels are unverified claims and no signed center-manager evidence, individual ID, license, clinical rights, payments or patient data are included.

It rejects stale/mismatched source identity, invalid snapshot contract, unsigned/unsorted/unsafe departments or physicians, unverified event types/flags or broken contiguous global event versions.
