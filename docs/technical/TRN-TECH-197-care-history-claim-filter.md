## Backend and precise paging semantics
The reader first verifies the **entire unchanged** case event+audit journal in one original PostgreSQL READ ONLY / REPEATABLE READ transaction and reconstructs full root and follow-up lineage/digests. If `expectedCurrentRevision` differs from current case revision, return HTTP 409 **even if the new event has another type**. Only then apply the selected action predicate to events whose **persisted source revision is greater than afterRevision**, preserving the original revisions with gaps (e.g. CONTACT revisions 2,4,6,8,10). Page limit applies to matches, not to a raw unfiltered slice; original persisted revision of the last returned match is `nextAfterRevision` only if another match exists after the last returned item. Terminal sparse or empty pages return `hasMore=false`, `nextAfterRevision=null`. No schema, role, event, domain reducer, new route or clinical inference.
