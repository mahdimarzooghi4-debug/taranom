# TRN-TECH-180 — DRAFT / Source-verified manual support-case handoff between member and center test workbenches

Date: 2026-10-18. Business basis: TRN-BIZ-045, TRN-BIZ-046 and the national multi-market product boundary. This is an engineering-only test workflow; no medical referral, authorized institution, complaint submission, member identification or transfer of records is approved.

## Existing contracts and intended capability
Both independent Persian demos already share the **same** canonical test-only PostgreSQL support intake journal (TRN-TECH-075): the Member Support workbench can append an unverified complaint/insurance dispute claim; the Center QA workbench can read and manually follow up the original event. The two panels had no source-pinned human handoff flow and relied on separately remembered identifiers or reading a broad test worklist. The new feature explicitly connects the existing interfaces without exposing a new server route or granting cross-context authority.

1. After the member workbench has a validated committed/read `TRN-TECH-075` support case with revision >=1 and no unresolved pending POST, render a readonly hand-carried JSON reference with exactly eight fields: `format='TRN-TECH-180-TEST-SUPPORT-HANDOFF'`, `version=1`, synthetic `caseRef`, synthetic `memberRef`, original topic, synthetic evidenceRef, canonical root `originalRequestId` and observed revision. The exported values are from the current source snapshot, never editable input guesses. If the claimed member in the form changes or a pending write exists, hide the handoff.
2. In the center workbench show a separate paste area and **explicit read-only human action**. Strictly reject malformed JSON, unknown fields, wrong version, non-synthetic refs, wrong topic, missing root UUID, non-positive/unbounded revision and oversize payload before making a GET. Then read **only** `GET /internal/demo/v1/support/{caseRef}` from the existing isolated PostgreSQL source. Require its `READ` envelope, all no-authority flags false, validated immutable event chain, exact original case/member/topic/evidence/root UUID and **exact current revision**. A stale receipt after another append requires a new human-exported receipt; no silent case advancement.
3. On success the center can read existing audit/history and use the prior independent manual command workflow (still all existing test-only constraints). On refusal leave the selected center case unchanged, clear any previously viewed snapshot and show a deny status; never trust a receipt as an access token, generate a new support event, open a clinical chart or contact a doctor. On manually changing the selected case, invalidate any cached/read result and in-flight GET using an incrementing request generation. No localStorage, cookie, URL query trust, real member ID, real evidence or medical data.
4. Clinical diagnosis, provider routing, insurance decision, communication, member consent, actual complaint intake, formal clinical appointment, real sponsor authority, credential issuing and any Production capability are **not** part of this Sprint. This handoff represents a reference to an unverified claim, not a medical referral or permission to read a person's care record.
