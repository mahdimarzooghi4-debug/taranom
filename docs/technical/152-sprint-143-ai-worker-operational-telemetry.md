# TRN-TECH-152 — Sprint 143: bounded, privacy-preserving synthetic worker operation counters

## Executable bounded implementation
The Kestrel .NET synthetic AI worker boundary now records **process-local monotonic counters** for a fixed classification set: admitted starts; fully HMAC-verified successful read-only completions; subprocess rejection; invalid/malformed cryptographic worker response; deadline exceeded; incoming HTTP caller cancellation; unavailable/other runtime failures; capacity denials; active and peak active subprocess invocations. Increments are atomic; a shared post-admission `finally` records a terminal outcome and releases the concurrency slot, including after errors.

The child process still cannot trigger any model training, activation, diagnosis or external AI API. No `requestRef`, tenant, actor, token, hostname, exception text, body, model artifact or clinical data enters the counters. Classification comes from typed internal failure kinds, **not** raw Python stderr strings or arbitrary untrusted codes. All HTTP failures still return only the pre-existing non-authorizing generic 503 except explicit capacity denial. No extra retry, fail-open recovery, worker command or clinical/financial state change.

An opt-in `GET /internal/demo/v1/ai-worker/telemetry` route exists **only** inside the inherited CI-ephemeral Kestrel host when both worker and admin QA gates are enabled. It inherits exact loopback host/forwarded-proxy rejection and independently rejects auth, cookies, tenant/role hints, origins and any query. Response includes only fixed numeric totals plus explicit `auditEvidence=false`, `operationalIdentityVerified=false`, `productionReady=false`, and all existing authority flags false. There are no Prometheus/OTLP credentials or externally routable endpoints.

## Mandatory tests
A new nondeployable `.NET` executable probe checks classification, peak/active counts, capacity and 400 concurrent lifecycle updates without dropped increments or identity-bearing dimensions. Real Kestrel→Python→SQLite HTTP tests verify that five sequential and 24 concurrent synthetic reads produce only correct successes or explicit capacity denials; read-only telemetry reports matching aggregate deltas, no stuck active child and a four-slot upper bound. Forged Authorization/Cookie/tenant/role/query attempts are denied; no signed frame/identity or request ref is returned. Both probes join the inherited full 14-job CI. All existing PostgreSQL backup/recovery and Chromium regressions remain mandatory.

## Limitations and unresolved dependencies
These memory-only metrics reset on every host restart and **are not** durable, tamper-proof or attributable audit records. They cannot justify real Production readiness, regulatory audit, clinical conclusions, model approval or human promotion. Proper external observability, service identity/OIDC + organizational grant/revocation, approved process isolation, lawful first-party datasets/consent, medical+technical human committee signoff and separate final human promotion are still unresolved.
