## Goal and exact bounded contract
Member nonclinical coordination has a canonical full PostgreSQL event timeline, but currently cannot inspect **what unverified contact and clinical-source claims existed as of an earlier journal version** or see the exact synthetic request/actor/root references underlying a claim without reading backend JSON. Add a history version explorer to the existing Persian Member coordination screen. Source is ONLY the existing GET `TRN-TECH-115` response already checked for complete contiguous events, UUIDv4 uniqueness, original submission/request and member lineage, claims type and the 13 real-world-denial flags. No new server endpoint, domain action, table, privileged role or trusted healthcare integration.

Once an independently verified snapshot has been read, offer an explicit version selector from 0 through its source revision. The read-only historical panel computes the exact prefix of that previously accepted immutable event sequence, displays **counts of claimed coordinator contacts and unverified clinical-source references at that prefix**, the exact synthetic origin/member/request UUID and actor/note lineage of those events, and labels which later source-backed events were appended after that chosen revision. Version 0 is the empty pre-request prefix; other versions are the first N immutable events. This is an *as-of display of one validated current journal*, not a second server historical snapshot, replay/reversal, actual member read receipt or clinical state.

Historical selection NEVER triggers a GET/POST or writes a backend case; it also never overwrites the current canonical `snapshot`. While viewing an earlier prefix, ALL new command buttons (including guided action) fail closed; returning to exact current revision restores the ordinary action preconditions. Case/claim input edit, manual fresh GET (including an independently appended Center event), source failure, new POST/ACK reconciliation or imported uncertain command resets the historical selection and hides any old history until a new validated snapshot is available. Uncertain command latch remains authoritative. No persistence across reload, polls, external member identity or real medical data.
