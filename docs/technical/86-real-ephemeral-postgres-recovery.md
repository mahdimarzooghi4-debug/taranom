- After the existing real Python→localhost ASP.NET→PostgreSQL + React Chromium end-to-end tests finish, use the already running sole PostgreSQL **18.6 service container**. Verify its container uniqueness and public-schema table allowlist (`internal_test_*`, including mandatory center/support event+audit tables). Read all rows as JSON and calculate order-independent canonical SHA-256 by table; also compare column schemas, triggers, indexes, constraints and independently assert paired support/center event/audit request+digest equality. A nonempty actual accepted event history is mandatory.
- Perform **genuine PostgreSQL custom-format pg_dump → createdb in the same ephemeral service → pg_restore into a newly created separate database**. No data is restored into the original, or outside isolated localhost CI. Backup is 0600 in private tempfile (0700 parent) with a fixed bounded file size; never uploaded as GitHub Artifact, printed, cached, persisted, shipped to vendor or included in logs.
- Recalculate identical table schemas/rows and verify append-only Event/Audit triggers still exist on the restored DB; attempt a no-op `UPDATE` against event tables and require the trigger to **reject** the mutation, then re-read both restored and source fingerprints to ensure no state drift. Fail closed on dump/restore failure, missing rows, corrupt audit linkage, inconsistent structure, unsafe tables, environment mismatches, missing container or restore guard violation.
- New unit tests cover exact ephemeral admission including production DB/host rejection, wrong/no CI env, table injection, missing required source tables, row hash content and order, subprocess errors and deliberate trigger-guard rejection. Real end-to-end PostgreSQL exercise is invoked as an added step of the **existing 14th shared CI job** after all browser suites, not a replacement or additional untrusted Docker image. Exact-head Push and PR must each show 14/14 success including this genuine restore.
- Output is only sanitized aggregate count of synthetic-only tables/records and flags: `production_recovery_verified=false`, `rpo_rto_verified=false`, `national_release_allowed=false`. The exercise does **not** simulate a Production outage, establish actual RPO/RTO, verify remote provider backup, encryption, secrecy outside CI, physical region, long-term retention or recovery approval.
