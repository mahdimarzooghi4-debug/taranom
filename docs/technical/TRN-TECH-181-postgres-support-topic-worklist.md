# TRN-TECH-181 — DRAFT / PostgreSQL-paged topic filters on the unverified support-case worklist

Date: 2026-10-18. Technical scope only; local synthetic support journal. NOT a medical triage, staff assignment, patient directory, insurer eligibility decision, case severity, service-level queue or legal complaints registry.

## Reason and authority boundary
TRN-BIZ-045 and TRN-BIZ-046 distinguish the coordination of an unverified service complaint from the professional/insurance entities that can actually investigate or decide. The Center QA currently reads an opaque test-case worklist (TRN-TECH-129) but cannot focus it by **the original submitted topic** without manually opening each row. In contrast, the fully separate organization/enterprise scoped journal cannot be joined to a member support case: no real delegated member consent or cross-context authorization exists. This Sprint adds only a topic-specific local view over the same support case journal and does NOT connect separate tenant resources.

## Precise contract
- Existing GET `/internal/demo/v1/support-worklist?afterCaseRef=<cursor>&limit=<limit>` remains valid and unchanged in meaning. An optional **single** `topic` query field admits exactly `ALL`, `MedicalServiceComplaint`, or `InsuranceCoverageDispute`. If absent, `ALL` is canonical. Reject unknown/duplicate/extra query keys, invalid cursor or bounds, and never infer topic from a note, a medical provider or member profile. Every accepted response includes the selected `topic`, preserves fixed deny flags, and still exposes only caseRef, revision and followUpCount per row.
- Use the existing **SELECT-only PostgreSQL reader** and a single `REPEATABLE READ` / `READ ONLY` snapshot. The SQL keyset filter is evaluated **before LIMIT** on the original `revision=1` command's canonical numeric `Topic` field; no post-page UI filtering or skipped pages. Stable `COLLATE "C"` ordering is unchanged. Select `limit+1` matching rows, and rehydrate **all matching rows including lookahead** through canonical event+paired-audit validation. If corrupt or mismatched, fail the entire request; never omit a damaged row, infer `ALL` or move to another tenant.
- In Center QA the Persian selector for **all**, **unverified medical-service complaint**, **unverified insurance-coverage dispute** is separately visible. Changing selection must clear any rows and cursor and load only when the user explicitly clicks. A returned topic that differs from the selected topic is rejected. Clicking a row continues to the existing independent single-case GET, historical read and manual audited note workflow; topic filter itself never performs a POST or selects a case automatically.
- No new table, index, DB role, API route, medical/legal/insurance authority, cross-org list, real member identifier or external API. Only the preexisting test `test:` case references and recorded unverified topic codes are returned. Production use prohibited.

Preserve unchanged legacy unfiltered tests, all 14 canonical CI jobs and real database restore; exact-head technical Code Review COMMENT only (not independent approval).
