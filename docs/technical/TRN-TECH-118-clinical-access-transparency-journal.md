## Functional gap and deliberate safety

Existing `SyntheticClinicalAccessTransparencyTrail` models, but did not durably store, three unverified *paper-only* requests: a claimed clinician requests a specific member/service/category, a claimed member raises concern, and a separate claimed oversight actor adds a note. The pure model assesses treatment-purpose disclosure prerequisites **without authorizing any actual medical record**. No real consent/identity/provider/clinician source, authenticated role, PHI, actual read, transmission, regulator incident decision or legal exception exists. The user wants substantive core capabilities, not another disconnected UI: implement an independent immutable technical source with reproducible read lineage. **No HTTP or UI, Production adapter, real authentication, clinical access or new business policy**.

## Scope and implementation

Add `PgSyntheticClinicalAccessTransparencyJournal` to the already friend-authorized `Taranom.ProofingJournal.Postgres` bounded test support project. It uses **only** `internal_test_clinical_access_case/event/audit` PostgreSQL tables with explicit request UUID/case, canonical numeric actions, version, original serialized synthetic scope, exact SHA256 digest and paired audit. Guard accepted event and audit against UPDATE/DELETE; source check always replays the unchanged original `SyntheticClinicalAccessTransparencyTrail.Apply` from revision 0 to pinned case header, rejects missing/changed audit/request/action/digest and failed domain transitions. Serialize writers by case header `FOR UPDATE`, atomic transaction with evidence+audit+version CAS, rollback rejected/stale/UUID conflicts and prevent concurrent double append. Read uses PostgreSQL `REPEATABLE READ` and explicit `SET TRANSACTION READ ONLY` for a coherent snapshot with no header locks; corruption fails closed before any projection. All identifiers are opaque `test:` fixtures; no credentials, clinical payloads, access tokens, patient data, external SDKs or calls.

Projection to alleged member **must go through original `ProjectForClaimedMember`** using independent claimed `SelfReadBoundaryInput`. A mismatched tenant/member or Sponsor/Employer returns zero history/counts and no clinical permission flags. Even a correct member with all caller-asserted Confirmed evidence receives only `UnverifiedPaperOnly`, counts and untrusted prerequisite state; `RecordReadOccurred`, `DisclosureGranted`, `LegalExceptionEstablished` always false. `test:` actor names are NOT independent authentication and SHA256 is not a DBA-resistant attestation. No real clinical disclosure whatsoever.
