## Verified defect and source-only scope

`PgSyntheticSupportJournal.ReadAsync` begins a default PostgreSQL READ COMMITTED transaction and invokes `RehydrateAsync`, which executes `SELECT current_revision ... FOR UPDATE` against the support-case header. That causes every synthetic member support GET (including immutable complaint/insurer-dispute history) to acquire a writer row lock, potentially waiting behind an unrelated uncommitted writer. Simply dropping `FOR UPDATE` on READ COMMITTED could mix header revision and event+audit revisions committed between multiple SELECT statements.
