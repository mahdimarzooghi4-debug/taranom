# TRN-TECH-186 — DRAFT / PostgreSQL-verified nonclinical care coordination worklist

Date: 2026-10-20. Based on existing TRN-BIZ-046 and TRN-TECH-115/184/185. CI-EPHEMERAL-ONLY, strictly synthetic `test:` cases, **not** a real patient/coordination directory.

## Identified functional gap and decision
Sprint 175 allowed Center QA to read, source-verify and append unverified coordinator-contact claims for a manually known care-case reference; Member could independently observe the original canonical journal. Yet Center could not find an existing synthetic request unless a user separately supplied a caseRef. There is no authorized member identity, delegated permission, consent or real clinical scope; introducing a general real user lookup would be incorrect. Add a *narrow* internal, read-only, synthetic worklist from the **same** audit-backed care journal. Never join to real Member, Organization, insurer or Clinical registries.

## Backend contract
- New explicit CI-only GET `/internal/demo/v1/care-coordination-worklist?afterCaseRef=<cursor>&limit=<N>`; exactly two single-valued keys, `afterCaseRef` may be empty, else only bounded `test:` syntax, `limit` exact decimal 1–10 with no leading zero. Reject duplicate/unknown query keys and malformed cursor. No POST or real member search route.
- Returns `contract=TRN-TECH-186`, `syntheticOnly=true`, `unverifiedClaimsOnly=true`, `source=VERIFIED_ISOLATED_POSTGRES_CARE_JOURNAL`, original cursor, limit, `hasMore`, `nextAfterCaseRef` and a max-N list of `{caseRef, revision, contactClaims, sourceClaims}`. Only **counts of unverified historical claims** are exposed: no memberRef, claimed coordinator, actor, note, evidence, clinical material, referral or actual status. All preexisting 13 real-authority denial flags remain false; the worklist cannot infer urgency, legitimacy or care completion.
- The actual PostgreSQL reader is the **separate least-privileged SELECT-only role** previously attested in TRN-TECH-172. Use one `REPEATABLE READ` + explicit `READ ONLY` transaction. Source query selects only `case_ref` with `current_revision>0` and exact `COLLATE "C"` keyset order, limit+1 lookahead. Every candidate including the lookahead is passed through existing `RebuildAsync` verifying serialized command SHA-256, original request/enum equality, full domain re-apply, contiguous revisions, immutable event with paired audit and exact header revision. Invalid first action, impossible follow-up count or source corruption fails the **whole** page, never silently suppresses or approximates a row. No arbitrary data inference, paging after UI filtering or user-supplied SQL; no schema, role or domain change.
- In the existing Center QA panel, a separate Persian list shows verified caseRef/revision/unverified claim counts; supports human-clicked first and next keyset pages and optional cursor. Changing cursor clears old rows and invalidates in-flight responses. Every returned page must match exact contract/cursor/limit, all denials, ordered synthetic case refs, counts and next marker; forged/failed responses show nothing. Clicking a row merely populates its caseRef into the existing manual single-case source-reader. **No automatic GET of private records and NO POST**; contact claim still requires separate source read, explicit human action and the Sprint 175/176 UUID/CAS/audit gates.
- CI-only loopback Kestrel, ephemeral PostgreSQL fixtures, no durable browser storage, user authorization or provider integration; never expose this unauthenticated endpoint in Production. The technical page-size limit is not a clinical/business criterion.
