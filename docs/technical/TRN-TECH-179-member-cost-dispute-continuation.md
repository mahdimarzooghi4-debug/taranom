# TRN-TECH-179 — DRAFT / human-carried continuation of the same unverified cost dispute

Date: 2026-10-18. Evidence-based functional UI, not an identity/insurance/legal authorization.

## Existing user journey and gap
Business TRN-BIZ-049 and TRN-BIZ-052 call for a unified experience of member-facing cost uncertainty and insurer-dispute follow-up. The CI-only React and PostgreSQL workbench already provides a canonical synthetic cost preview, an independently scoped synthetic support dispute, append-only member-chosen cost statements, follow-up notes and two-journal relationship reattestation (TRN-TECH-095/097/099/100/178). After a page reload, a user currently must retain and manually re-enter at least the preview UUID and separate caseRef without an integrated continuation handoff, increasing accidental case mix-up. Browser does not have real member authentication, so no automatic cross-case discovery is authorized.

## Contract
- After a successful **existing independent cost/support journal relationship attestation**, show a copyable **human-held test-only continuation locator** with a deliberately versioned format, exactly: format='TRN-TECH-179-TEST-CONTINUATION', version=1, previewId, memberRef (synthetic), previewRevision, previewFingerprint, choiceRevision and caseRef. This is NOT a bearer credential, permission, proof, logged-in session, or independently signed envelope. It contains no health data, amounts, passwords, notes, identifiers of real members or external services.
- After reload, user must FIRST manually read the exact source cost preview UUID from PostgreSQL. Only then allow an explicit paste-and-click continuation action; never perform a background discovery, automatically issue a POST or store data in localStorage, sessionStorage or a cookie. Strictly reject unknown fields, absent/incorrect format, oversize content, malformed/synthetic-invalid caseRef, mismatched preview/member/revision/fingerprint/choiceRevision against that current independently validated cost source.
- The existing PostgreSQL `support-link` GET is necessary even after all fields match, and must attest exact source preview, caseRef, matching member and fingerprint, **exact current cost choice revision** (not a greater revision), valid synthetic-denial flags, at least one canonical support event and independently reattested non-atomic two-journal references. Failed, changed or unavailable GET must show a refusal and leave the existing caseRef unchanged, not silently suggest that a ticket authorizes the user. On success the same existing audited follow-up and timeline controls resume, but nothing is submitted without a further user action.
- A changed preview identity or choiceRevision must remount the child support workbench and discard potentially stale linked results, pending commands and locators from the *old* preview source; do not carry this state across cost version boundaries. No cross-journal atomic transaction or insurance adjudication.
- No new backend route, journal schema, financial calculation, clinic, insurer, authentication scheme, real personal data, provider, credit or real sponsor action.

## QA and gates
Three actual Chromium + Kestrel + PostgreSQL tests: (1) two-event insurance-dispute with recorded follow-up survives reload through source preview read + pasted locator + independent relationship verification, supports read-only historical timeline and makes **zero** new POSTs; (2) a forged/unrelated caseRef or memberRef never adopts a different case or enables details; (3) previous locator is rejected when a new synthetic choice changes preview's current choiceRevision, without a link GET or write. Full existing 14-job canonical CI, exact-head technical COMMENT and Draft/Open/Unmerged PR required. Tests are CI-only and do not provide independent human approval. No Stage, QA Gate, Release Approval, Merge, Production. First comprehensive national three-market launch remains DENIED_BY_DEFAULT.
