# TRN-TECH-073 — Ephemeral Center Workflow, Real PostgreSQL + .NET + React (test-only)

**Date:** 2026-10-11. **Parents:** TRN-TECH-005 (.NET operational ownership), TRN-TECH-071/072 actual localhost real HTTP/React smoke, approved product center/department/doctor-affiliation design implemented by Sprint 06 \`ClinicalCenterJournal\` and \`PgClinicalCenterJournal\`, and national release constraints TRN-BIZ-028/030/040. **Review status:** implementation demonstrator, not a public code authorization for clinical operations, professional licensing, or an authenticated center API.

## Problem and substantive improvement

Existing test-only .NET center domain and append-only PostgreSQL journal support four coherent operations, repeat detection, revision checking, transactional audit, and reconstruction, yet the user cannot exercise a complete browser→HTTP→domain→PostgreSQL→browser workflow. This package makes that **real** across the layers and uses existing implementation, rather than adding another synthetic pure reducer or management dashboard. It is a controlled **test-only vertical integration**: it neither creates a real healthcare center nor claims a trusted clinical actor.

## Exact self-contained boundaries

- Separate **nondeployable** \`Taranom.CenterWorkflow.Demo\` Web SDK host binds exclusively loopback **port 4320** and **refuses startup** unless \`TARANOM_CENTER_DEMO_TEST_ONLY=CI_EPHEMERAL_ONLY\` and \`TARANOM_TEST_PG\` points to **localhost port 5432, exact database \`taranom_sprint64_center\`**. The test database is ephemeral in GitHub Actions. No public IP, IdP, bearer session, real patient/provider/clinical/license, wallet or bank content. References are strictly \`test:[A-Za-z0-9_-]+\`; reject others before DB work. No actual manager authorization is implemented; positive \`CenterEvidence\` values injected **only** as controlled test harness inputs and never passed off as signed identities.
- The host references **existing**, unchanged \`Taranom.ClinicalCenterGovernance\` and \`Taranom.ClinicalCenterJournal.Postgres\` via narrowly scoped \`InternalsVisibleTo\`; it calls existing journal \`ApplyAsync\` / \`ReadAsync\` and initializes only isolated \`internal_test_center_*\` tables. The inherited journal already has transactional event, audit and materialized projections, append-only DB guards, stale-version/idempotent request replay and replay-integrity verification. No parallel business reducer, new ledger or competing storage path.
- Local **GET** \`/internal/demo/v1/centers/{test:centerRef}\` reads an absent/new case without materializing it, or returns current revision, departments, doctors' **pending independent verification / ended** affiliation, assignment IDs, event count. **POST** \`/internal/demo/v1/centers/{test:centerRef}/commands\` accepts only the **exact five-field** JSON \`requestId\` (nonempty UUID), \`expectedVersion\` (nonnegative integer), \`kind\` (DEFINE_DEPARTMENT / RECORD_DOCTOR / ASSIGN_DOCTOR / END_DOCTOR), optional \`departmentRef\` and \`doctorRef\` with strictly action-appropriate presence and \`test:\` syntax. Duplicate fields, extra actor/authorization claims, oversized (768-byte) and malformed payloads are denied. The server derives target/acting center from route **only**; callers cannot choose an independent acting center, membership or tenant or assert a real legal authority.
- Applied/identical replay → HTTP 200 with exact current version; stale/conflicting replay or non-applicable change → 409; malformed → 400; forbidden cross-origin → 403; inaccessible/corrupt journal → 503 with redacted text, never fabricated state. Every successful DTO explicitly carries \`syntheticOnly=true\`, \`managerAuthenticated=false\`, \`professionalQualificationVerified=false\`, \`nationalReleaseAllowed=false\`. No wildcard CORS, browser cookies, member IDs or accepted professional credential. GET has no write and POST cannot create authorized business authority. Browser security headers set no-store, nosniff, frame DENY, CSP default deny. THIS DEMO IS NOT A PRODUCTION API.
- Separately built, pinned React 19/TypeScript/Vite \`center-demo-web\` is served same-origin by the test-only host. Persian RTL journey includes selecting only test IDs, reading the durable current revision, defining a section, recording an **unverified** doctor affiliation, assigning the doctor to a section, ending that affiliation, and reloading persisted state. It explicitly distinguishes network/journal failure from zero records, shows declined conflicts, and never displays clinical permissions or verified medical qualification.
- Add **14th CI job** with real ephemeral PostgreSQL 18.6, actual .NET 10 compile/start, React build, Python genuine HTTP sequences including idempotency, conflict, stale state, separate centers, disallowed real IDs/actor fields and forbidden origin, plus **five Chromium** browser tests of the complete UI/API/DB workflow, error and denial paths. All inherited 13 jobs keep running. The new host is not built into or promoted as the member or center Production app. No Stage/QA Gate/Release Approval/Production, no Ready or Merge, Code Review initial COMMENT only.

## What is not delivered

No real clinic provisioning, KYC/IdP authentication, center manager, medical licence verification, healthcare professional qualification approval, patient clinical rights, legally valid record, insurer, PSP, payment, national provider network or external integrations. A successful \`test:\` workflow demonstrates working code and durable isolated database behavior only. Its current authority checks are simulated **in the test harness** and must **never** be connected to genuine data. No accepted production role contract or vendor/hostname is inferred. Real authenticated center workflows remain separately blocked, as do all 17 national release dimensions and the full comprehensive nationwide three-market official launch (\`DENIED_BY_DEFAULT\`).
