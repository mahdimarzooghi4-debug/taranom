# TRN-TECH-158 — Sprint 149: external Worker custody discovery, denial-only

## Business and architecture boundaries
The preceding Worker evidence test chain (Sprint 145–148) establishes synthetic SHA-256 history integrity, a verifier-held HMAC checkpoint, a bounded offline ZIP receipt, real Kestrel restart and POSIX Linux account separation. Crucially, **the sudo-capable CI runner, GitHub workflow authors, code owner and root on that same machine retain administrative power over all secrets and material. This is not independent external custody.**

The project already has TRN-TECH-064, -079, -082 and -121, which separate byte-level external evidence intake integrity from independent review and official approval. This new artifact does not replace or weaken those rules. The independent organization, Production hosting/recipient, legal authority, authorized service identity, cryptographic receipt policy, secrets policy and retained artifact lifecycle **have not been selected or approved**.

## Implemented offline discovery contract
`docs/governance/ai-worker-external-custody-template.json` contains only schema/version/scope and `candidate:null`. A strict, bounded, no-network Python evaluator in `tools/qa/check_worker_external_custody.py` reports this exact template as `EXTERNAL_CUSTODY_NOT_CONFIGURED`. It contains nine **questions for future independent human assessment**, not approved numerical criteria or Production gates: separate administrative control, custodian authority, receipt provenance, off-host anchored history, retention/deletion authority, privacy/data rights, secure recipient/transport identity, incident recovery, and independent human/legal review.

The candidate can offer strictly allowlisted, opaque **claim references only**, never real documents, tokens, URLs, personal data or signatures; the evaluator never dereferences them. A partial set is `EXTERNAL_CUSTODY_CLAIMS_INCOMPLETE` and a syntactically complete set is `EXTERNAL_CUSTODY_CLAIMS_REQUIRE_INDEPENDENT_REVIEW`. In both cases, **external receipt verified, independent custody verified, retention/privacy authorized, human release approved, Production ready and national release allowed are always `false`**. Any fabricated `approved_by`, `production_ready`, external authority/status or unsupported property is rejected as `DENIED_INVALID_EXTERNAL_CUSTODY_CLAIM`. No evidence/ref contents echo into reports.

Test cases include all-claims-still-blocked, missing topics, untrusted URLs/tokens/path-like references, unexpected promotion fields, wrong schema/scope, duplicate JSON keys, malformed UTF-8, NaN, oversized files, symlinked inputs and no-clobber/owner-only 0600 report. This runs inside the existing mandatory 14-job suite alongside national `DENIED_BY_DEFAULT`, actual PostgreSQL and Chromium regressions. The only checked-in input is the empty public template and no secrets or real external artifacts are permitted in CI.
