Date: 2026-10-19. Scope: exact technical correction to synthetic, CI-ephemeral Sprint 172 topic worklist; no new member/organization authority, clinical decision or policy.

## Verified security defect in the previous source predicate
TRN-TECH-181 introduced a PostgreSQL `WHERE first_event.command_json::jsonb ->> 'Topic' = @topic` to apply a filter before the keyset page LIMIT. The event's `command_json` is **not an independently trusted index**: its real immutable integrity proof is the separately stored SHA-256 `event_digest` and paired audit, recomputed by canonical `RehydrateAsync`. Filtering on that raw JSON before rehydrating makes a damaged first event **disappear from the result** whenever its topic is forged to a different permitted topic. A paged response may incorrectly look clean, while a direct single-case source read would fail. The existing DB trigger denies runtime mutation, but owner-level corruption or storage failure must still fail closed.

## Replacement source contract and non-invented guarantees
- Keep the same `GET /internal/demo/v1/support-worklist` route, exact optional topic vocabulary `ALL/MedicalServiceComplaint/InsuranceCoverageDispute`, strict input rejection, reduced rows, keyset cursor, and no-authority flags. No new public API, role, table, storage, index or access grant. Reader remains the **separate SELECT-only PostgreSQL principal** and uses one `REPEATABLE READ` plus explicit `READ ONLY` transaction across the complete response.
- Scan `case_ref` in ascending `COLLATE "C"` bounded **transport batches** (64 candidates per SELECT; NOT a policy threshold), after the supplied source cursor; SQL never uses untrusted `command_json` to decide which candidates to skip. For every encountered candidate, including cases whose original topic will ultimately be excluded, **first** call the original `RehydrateAsync` which recomputes the SHA-256 digest over exact `caseRef | revision | serialized JSON`, verifies request UUID, revision continuity and the independently paired audit for the entire event history. Check that the case has valid nonempty history and bounded follow-up count.
- **Only after complete verification**, compare the canonical first command's enum `Topic` and collect source-valid matches until `limit+1` matches. That is logical topic filtering **before the returned page limit**, with no UI post-filter, missing pages, fabricated list position or made-up outcome. A failed/invalid event in any scanned prefix, even if it would have been filtered out by topic, aborts the complete response with 503 and zero rows. Cases past the reached lookahead need not be scanned until their page is requested; this is not a global database certification.
- Single-case reads/writes, existing append-only triggers, header CAS, event+audit hashes, exact owner/reader roles and the human-controlled UI remain unchanged.
- This correction accepts additional source rehydration work for sparse topic filters instead of silently filtering unverified JSON. Performance benchmarking on a real authorized target is required before operational-scale promises; no real dataset or production performance is claimed.
