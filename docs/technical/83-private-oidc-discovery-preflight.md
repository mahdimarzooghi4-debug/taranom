## Need
An operator with an independently *authorized, selected* authentication IdP needs a safe technical way to test read-only **OpenID Connect provider discovery** beyond basic TLS reachability. A TLS handshake alone does not confirm that the vendor advertises a viable browser authorization-code/S256/OIDC discovery contract. Do not choose a vendor, enter an actual account, or infer national operational readiness.

## Exact bounded scope
- New stdlib-only `tools/policy_checks/check_private_oidc_discovery.py` supports **no-network default** `TARGET_NOT_CONFIGURED`. Real opt-in needs owner-only private 0600 target hostname file outside Public Git and new-only owner-private 0600 report in a 0700 directory; validate BOTH boundaries before network. Reuse the existing private host reader, valid public-domain and DNS-all-global restrictions. Host/IP/partner secrets are never included in public reports or GitHub CI.
- In operator mode: one DNS resolution, fail closed for ANY non-public address, then one outbound 443 TLS 1.2+ CA/SNI verified handshake to the selected numeric IP, peer-IP check, no downgrade. Send precisely one credentialless GET of root-level `/.well-known/openid-configuration` with `Host` pinned to same selected DNS name; no cookies, credentials, browser callback, token, JWKS fetch, arbitrary path, redirects, HTTP retries, or cross-domain navigation. Enforce JSON content type, bounded 64 KiB response, reject redirects, invalid/unexpected HTTP and compression, forbid XML/HTML.
- Strictly and only inspect returned metadata syntax against **exact** `https://<selected root-host>` issuer (root issuer only, no realm path), three same-host HTTPS 443 authorization/token/jwks endpoint URLs without credentials/query/fragments, advertised `code`, `S256`, supported subject types and a non-`none` asymmetric signing algorithm. Nonmatching/malformed metadata fails closed. Cross-host endpoint topology, path-based issuers, token authorization or arbitrary algorithm/trust selection are **not approved by this limited preflight**, and need a future explicit partner-specific technical contract. Signatures, keys, token validation and IdP legal authority are not proven.
- Positive output **`DISCOVERY_SYNTAX_OBSERVED_NOT_AUTHORIZED`**, not IdP approval or real login; all authentication, provider contract, membership activation, payment, protected records and national-release boolean flags are always false. Unconfigured mode remains `TARGET_NOT_CONFIGURED` without outbound network. Any unexpected error redacts host/IP/raw response.
- Offline CI mocks DNS/TLS/socket/HTTP and tests the actual fixed GET, numeric-IP DNS pin, SNI and certificate policy, redirects/SSRF/forged cross-host metadata, malformed JSON/duplicate keys/content-type/body bound, failclosed absent PKCE/code/alg, private target & report permissions, no network with absent target. No real identity provider is contacted by Actions. Integrate with canonical 14-job Push+PR full regression, strictly allowlisted new same-repository dispatcher.

Reference: [OpenID Connect Discovery 1.0](https://openid.net/specs/openid-connect-discovery-1_0.html), notably mandatory issuer equality, HTTPS metadata and response types; this tool intentionally adopts stricter same-host root-issuer-only constraints for absence of an approved multi-domain topology.
