# TRN-TECH-148 — Sprint 139: least-privilege disposable PostgreSQL AI denial journal

## Actual backend implementation
In Sprint 138 the test-only AI-admin denied-command Kestrel handler used the owner PostgreSQL datasource. Sprint 139 removes that datasource from the AI HTTP journal path. During isolated bootstrap only, the schema owner initializes the existing immutable denial table, mints two unrelated login roles, grants the writer exactly SELECT + INSERT on `internal_test_ai_admin_denial`, and grants the reader exactly SELECT. `NOINHERIT`, `NOSUPERUSER`, `NOBYPASSRLS`, `NOCREATEROLE`, `NOCREATEDB`, `NOREPLICATION` are mandatory; roles have no inherited memberships and no DML on any other `internal_test_*` table. All owner DB access stays out of the HTTP AI handler, including audit reads. The roles and passwords are CI-only ephemeral credentials minted separately on the GitHub runner; neither is shared or checked into the repository.

Each restricted NpgsqlDataSource connects as its own DB principal. Startup independently verifies `session_user=current_user`, role attributes, no memberships and effective SELECT/INSERT/UPDATE/DELETE/TRUNCATE over **all** current `internal_test_*` public tables, rejecting privilege drift before accepting HTTP. Read uses the reader connection, append uses the writer. Transaction-scoped PostgreSQL advisory lock, full canonical denial-chain verification, idempotent exact replay, append-only trigger and denial responses remain unchanged. No new admin operation, role grant, model approval or Production activation is permitted.
