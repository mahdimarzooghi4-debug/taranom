# TRN-TECH-156 — Sprint 147: bounded offline synthetic evidence handoff

## Objective
Deliver a **portable, read-only and test-only** Worker evidence packet from a verifier process to a separately invoked receiver process without selecting a Production storage provider, organization authority, legal audit regime or network/API transport. This extends the pre-restart HMAC checkpoint in TRN-TECH-155 and the actual .NET-to-Python two-epoch test history in TRN-TECH-154.

## Implemented protocol
The verifier confirms the HMAC checkpoint and actual two-epoch Worker ledger, then creates once an offline ZIP containing **only** the synthetic `worker-evidence.jsonl` and fixed-field `handoff.json`. The ZIP is bounded (<530000 bytes), uncompressed, constant membership/order, canonical ASCII manifest, regular-file entries, no paths/traversal and no keys or credential tokens. The exporter signs a separate, verifier-held receipt with the already ephemeral custodian HMAC key. It fixes ZIP SHA-256, ledger SHA-256, manifest SHA-256, final ledger head, and anchored record count. The receipt is **not bundled**, never shipped to the Worker, and both checkpoints and the HMAC key remain within a 0700 verifier temp directory. All generated files use exclusive creation and mode 0600; existing files are never overwritten.

A separate command validates the copied ZIP under a distinct 0700 CI receive directory against the original verifier-held receipt and key. It checks exact envelope length, enum/epoch/read-only flags, strict entire ledger SHA-256 sequence and two-epoch Boot→Success, anchored prefix and final digest, archive digest/receipt HMAC, allowed ZIP members, no extra/symlink entries, duplicate/path traversal and permission constraints. The receiver does not ask Kestrel/Worker to retry, train, decide or change a model, and has no route that can upload a package. Unsupported, altered or missing evidence fails closed, with generic redacted denial.

Independent AI unit tests exercise copied-packet verification, changed bundle bytes, replacement using fully recomputed internally valid public SHA-256 hashes, extra/misordered ZIP entries, modified/missing receipt or key, permissive permissions, symlinks, bad destination and disabled gates. The existing full regression performs the real Kestrel restart, prefix anchoring, Python independent ledger verifier, then exports, copies **only** the ZIP to a fresh receiver directory, and verifies in a separate Python process. No canonical regression is dropped.

## Honest limits
**This is NOT a real independent custodian.** Both directories and HMAC key are accessible to the same runner OS owner; a privileged compromise can replace both the key and receipt. There is no online sending, approval, external WORM retention, signed third-party acknowledgement, independent timestamp, production custody, multi-replica ledger, legal audit, recovery objective, real human actor, first-party patient data or service identity. No external company, bucket, policy thresholds, hosting, credentials, AI provider/runtime or medical committee is chosen. All output explicitly carries `auditEvidence=false`, `independentCustody=false`, `productionReady=false`. The ZIP contains only synthetic outcomes and epoch identifiers, no clinical or administrative data.
