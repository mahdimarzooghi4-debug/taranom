# TRN-TECH-173 — DRAFT / synthetic proofing PostgreSQL least privilege and MVCC reader
Date: 2026-10-18. An internal CI-only security hardening proposal, NOT approval of KYC, membership, national identity, financial or clinical functionality.

## Existing risk and source
The TRN-TECH-113 local proofing/correction journal maintains an auditable append-only PostgreSQL event stream, paired audit, denied-command audit and deterministic case/identity revision transitions. Previously both GET and POST used the schema-owner connection and even a read path acquired `FOR UPDATE`, conflating read/write permissions and tying request latency to row locks.

## Narrow implementation
- After creation of all other CI synthetic tables, create two completely distinct ephemeral PostgreSQL principals with **independent cryptographically random 32-byte credentials**. Writer gets SELECT/INSERT/UPDATE on `internal_test_proofing_case`, SELECT/INSERT only on event and paired audit, and INSERT-only on `internal_test_proofing_denial` to preserve rejected-command audit without allowing reading private rejection history. Reader gets SELECT only on proofing case/event/audit, no access even to denial audit.
- Both roles are non-admin, non-superuser, NOINHERIT, no schema CREATE, no historical UPDATE/DELETE and no access to the synthetic care, support or late-evidence case tables. Enforce exact role attributes and every table privilege via PostgreSQL, and **execute real denied SQL** as both runtime roles (writer event DELETE, reader header UPDATE, cross-domain SELECT, rejection-audit SELECT) requiring SQLSTATE 42501. Mismatch fails startup.
- Strictly guard this capability to `CI_EPHEMERAL_ONLY` and PostgreSQL database `taranom_sprint64_center` on loopback port 5432. The privileged schema-owner datasource remains only for DDL and creation of restricted roles; proofing HTTP handler receives only restricted writer/reader sources, disposed with application lifetime.
- GET now starts REPEATABLE READ and `SET TRANSACTION READ ONLY`, reconstructing case header/event/audit from one MVCC snapshot **without FOR UPDATE**; POST retains original case row FOR UPDATE, version CAS, event+audit+denial transactional guarantees. No new endpoint, event/schema field or sensitive identity data. Records are synthetic `test:` references and existing denial flags remain false.

## Tests, gates, limits
The canonical full 14-job CI includes actual isolated ASP.NET/PostgreSQL proofing cases: 3-step identity revision, mismatched review, idempotent replay, concurrent/CAS, rejected-command audit, failed audit atomicity and Chromium ACK recovery. Startup itself exercises actual permission-denied SQL for both roles and fails before serving any HTTP if isolation is compromised. CI green is only reproducible nonproduction verification, not independent human approval.
