# TRN-TECH-189 — DRAFT / Portable manual recovery for synthetic care commands

Date: 2026-10-20. Business boundaries TRN-BIZ-046 and independent TRN-BIZ-035/036/043. Technical source: TRN-TECH-115/167/184–188 and existing support-command manual recovery TRN-TECH-092.

## Functional gap, existing contract and scope
Both Member and Center coordination UI persist their one uncertain POST's original JSON/UUID only in volatile React state. Reload loses that source-pinned command, preventing reliable explicit read-only reconciliation/replay of an ACK-lost write. This sprint adds a **user-copied text receipt**, independent of browser storage, for each of the two existing test workbenches. It does not introduce credential, identity, clinical consent, medical upload or new server state.

The exact original canonical JSON command body and caseRef are enveloped in `{contract:"TRN-TECH-189",syntheticOnly:true,surface:"MEMBER"|"CENTER",caseRef,body}`. It is NOT a signature, token or authentication grant. The parser requires exact five envelope keys, exact eight command keys, canonical JSON with no duplicate/extra fields or data transformations, UUIDv4, consistent initial/follow-up action shape, root/actor/source fields and bounded `test:` references. Center can import follow-ups only. Cross-surface substitution, real refs, malformed JSON, unexpected keys and changed action structure fail closed. No claim about authenticity of a user-pasted receipt is made.

A pending command's receipt is visible before HTTP reply; after a reload the user must explicitly paste and click **Import (no GET/POST)**, which freezes other writes and replaces any old source snapshot. Only a second independent user click can request GET-only original event verification, or exact byte-for-byte body/UUID replay via the existing endpoint and PostgreSQL CAS/idempotency. Original journal verifies full scope/action/version/idempotency: an uncommitted, stale, conflicting, forged or out-of-scope command can NEVER be inferred as accepted from the receipt. A successfully committed event requires independent canonical PostgreSQL GET as before.

This is strictly CI-loopback `test:` with no localStorage/sessionStorage, no new API/table/domain/role, no signed medical document, clinical verification, member consent, physician authorization, real provider referral, payment, external AI or Production release.
