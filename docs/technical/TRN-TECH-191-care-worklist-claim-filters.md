## Operational gap and bounded contract
The existing center worklist (TRN-TECH-186) enumerates cases in opaque keyset order and displays counts of unverified contact/source claims, but it cannot locate a known category among many synthetic requests without manually paging every case. Provide a manually chosen `claimFilter` for factual EXISTENCE only: `ALL`, `HAS_CONTACT`, `HAS_SOURCE` or `HAS_BOTH`. These are never readiness, urgency, absent care/response, completion, member eligibility or coordinator task assignments.

The existing CI-only GET `/internal/demo/v1/care-coordination-worklist?afterCaseRef=&limit=4` remains backward compatible and defaults to `claimFilter=ALL`. An optional third single-valued `claimFilter` is allowed; all other/duplicate keys and invalid/clinical filter values return 400. The response repeats the chosen canonical filter so a stale/mismatched or forged page cannot be shown. All 13 authority denial fields and existing `TRN-TECH-186` source contract are preserved.

The server's independent least-privilege PostgreSQL reader runs one REPEATABLE READ / READ ONLY transaction, verifies each candidate with the original complete event+audit SHA-256 and canonical domain reducer, computes contact/source counts from the rebuilt immutable journal, THEN evaluates the filter, THEN applies the matched-case keyset page limit+lookahead. Applying the filter only to a raw N+1 slice would skip eligible cases and is forbidden. A bounded scan cap of 512 candidates for a filtered read returns fail-closed 503 if insufficient matched cases exist to prove complete pagination within the cap; no silent incomplete result or invented next cursor. The ALL path preserves the original bounded limit+1 read and behavior. No other database role, schema, event, identity join, endpoint or write changes.

The existing Center Persian UI uses a controlled select. Selecting a filter invalidates old rows, next cursor and in-flight results; every returned page must match exact filter, cursor, fixed UI limit, ordered `test:` cases, count invariants and authority denials, plus each row must match the chosen factual predicate. Selection only changes the existing caseRef field; independent single-case GET and deliberate human POST remain required. No auto-action or member PII.
