# TRN-TECH-119 — Versioned synthetic provider-quality and incident-handoff source

**Sprint 110; 2026-10-13.** Accepted Business: TRN-BIZ-043, 044 and 045. Parent Draft PR #120 at `633cbb717a2e57ed51693b9d33856fa5c93bc20e`, Push #38405275283 and Mainline PR #38405282669 both successful 14/14; prior review COMMENTED only.

## Problem and narrow scope

The existing `SyntheticProviderQualityTrail` and `SyntheticProviderNetworkEvidenceGate` distinguish direct providers from licensed partner networks and separate Taranom quality oversight from the partner network's own responsibility. However the quality timeline is only a pure, in-memory technical model. It cannot yet demonstrate ordered, concurrency-safe audit history after transaction restarts. This Sprint adds a **new independent test-only PostgreSQL source**, not a new qualification or financial authority.

A source first claims a `RecordUnverifiedQualityScope`, pinned to exact tenant/provider/service/path/network; the existing domain permits `RecordUnverifiedTaranomStandardNote`, a network-only `RecordUnverifiedNetworkProviderControlNote`, or `RecordUnverifiedIncidentHandoffReference` with untrusted actor/evidence/recipient markers. These are paper claims only, NEVER verified qualifications, contracts, actual doctor records, true incident notifications or reviewer decisions. This Sprint does not use qualification EvidenceGate output as authorization or create any approval, suspension, payment, clinician/clinic activation or emergency handling.

## Technical acceptance

- Reuse canonical `SyntheticProviderQualityTrail.Apply` unchanged. Add only `internal_test_provider_quality_case/event/audit` to the existing friend `Taranom.ClinicalCenterJournal.Postgres` test bounded context. Schema has explicit action allowlist, exact per-case UUID uniqueness, original command JSON and source-bound SHA-256 digest, immutable accepted event and transactionally paired audit with UPDATE/DELETE guard. Write locks one case header `FOR UPDATE`, CAS, rollback invalid/replayed/stale commands; accepted append and audit are one atomic transaction across replicas.
- Read exactly one PostgreSQL `REPEATABLE READ` and `SET TRANSACTION READ ONLY` snapshot without writer row locks; rehydrate the **entire** ordered lineage using the original reducer, verify contiguous revisions, stored request UUID/action, exact digest/case binding and paired immutable audit. Corrupt history returns a fail-closed integrity exception. An absent case reads empty and does not create data. Original `SyntheticProviderQualityProjection` exposes only **counts of claimed notes**, never a licensure/incident/quality outcome, rating or national capacity metric.
- Enforce synthetic case/tenant/provider/service and path/network only; no real entity IDs, professional certificates, credential content, health data or protected party names. Internal test role is deliberately limited to header DML and event/audit SELECT+INSERT (no UPDATE/DELETE); DB owner can still recreate fake valid history, so digest is not a digital signature or Production audit.
- Seven genuine isolated PostgreSQL xUnit tests: direct and network path separation, three accepted note stages and matching event+audit, correct/incorrect provenance, historical UUID replay/conflict, domain rejection, two competing writers one accepted/one stale, injected header corruption denied and role unable to change immutable events. No changes to the existing Center workflow or source of actual member complaints. No public HTTP/UI, external credential/partner/clinical network APIs, money, billing or medical incident transport.
