# TRN-TECH-167 — Sprint 158: bounded synthetic command HTTP ingress

This sprint closes a concrete transport fault on the existing operational **test-only** PostgreSQL case workflows: bounded-body readers formerly waited indefinitely for a caller that declared Content-Length and sent only a prefix while leaving TCP open. Command execution was guarded by source-only contracts but not a pre-persistence intake deadline. A slow request could hold request resources; in this sprint it cannot silently wait indefinitely or cause a partial command to commit.

## Contract
Reusable `SyntheticCommandIngress.ReadAsync` applies an explicitly CI-only **four-second** linked RequestAborted intake deadline, preallocated maximum bytes plus one sentinel, a declared Content-Length versus received-length comparison, a 2-byte minimum, exact upper bound and cancellation propagation. This is not a Production SLA, retry/timeout policy or real clinical requirement. It executes before parsing, CAS, transaction or journal persistence on the four existing real localhost:4320 synthetic PostgreSQL command routes: coordination, member support, identity-correction/proofing, late-evidence. On cancellation the route returns generic 503 and its original denial-only flags, never a fabricated 200/ACK, and no event/audit row can be written. Invalid completed frames remain ordinary 400. Valid exact commands, already implemented UUID replay, optimistic concurrency, append-only PostgreSQL audit and follow-up workflow remain unchanged.

Real Python TCP socket integration `tests/center_demo/test_synthetic_command_ingress_timeout.py` sends HTTP headers declaring 300 bytes while leaving only a partial JSON prefix on an open socket for each of four routes, waits for the bounded non-success response, then queries the same real PostgreSQL case and confirms no events or authorization flags. Runs concurrently under canonical full-stack CI alongside all original authentic domain tests. Existing browser, clinical denial, journal recovery, Worker custody and all 14 regression jobs remain intact.
