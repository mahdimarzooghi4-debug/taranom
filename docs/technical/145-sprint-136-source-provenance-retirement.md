# TRN-TECH-145 — Sprint 136: technical source provenance and retirement

## Delivered backend contract
The internal Python test-only AI control plane gains an **append-only per-tenant provenance event ledger** with contiguous sequence, previous-event SHA256, canonical event SHA256, immutable database UPDATE/DELETE triggers, and strict exact-schema/idempotent request handling. `CLAIM_RECORDED` contains only `test:` metadata: source ref, subject ref, TRAINING/EVALUATION partition, declared content digest, and **claimed**, not verified, separate consent and rights-review refs. The `SOURCE_RETIRED` event holds only a mandatory synthetic reason ref. Events cannot be reversed or overwritten by this slice. Both actions are available via local CLI and original opt-in loopback API `POST /internal/ai-test/v1/source-claims` and `/source-retire`; neither accepts real identities, subjects or personal records. Read-only inventory includes non-authorizing provenance event counts and last event digest.

The new `guard_manifest` reads and verifies the full event chain within the **same BEGIN IMMEDIATE transaction** as Dataset freeze, independent synthetic evaluation, Shadow fitting and held-out benchmark. Once any source is tracked for a tenant, all frozen sources must have exact corresponding claims. A retired source forbids new datasets, training, benchmark and **same-request replay**, including when its record was frozen before retirement; mismatch, missing source, tampering and cross-tenant misuse fail closed. Legacy test-only datasets that never registered technical source claims still operate in the original bounded CI sandbox, but **remain unverified, ineligible for real training and non-production**. This migration mode is not a real-world policy or lawful consent substitute.

## Authorization and limitations
Metadata refs are never checked against an external consent provider or clinical record. A SHA-shaped `source_sha256` is a **declaration**, not an attestation to real input bytes or evidence of permission. Even if technically consistent, all results preserve `legal_consent_verified=false`, `real_data_eligible=false`, `production_allowed=false`; no model or data is promoted. True operational consent withdrawal, retention, deletion and legal erasure semantics require a separate approved source and policy contract and must not be inferred from synthetic retirement. Per-tenant untrusted loopback test principals do not confer administrative authorization. No Stage/QA/Release/Production or merge is authorized.
