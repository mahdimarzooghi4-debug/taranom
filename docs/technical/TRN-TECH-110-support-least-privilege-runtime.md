**Date:** 2026-10-13 | **Sprint:** 101 | **Accepted business boundaries:** TRN-BIZ-045/048/050 complaint/insurer responsibility must be independently authorized; TRN-BIZ-028/030/040 nationwide release gates. **Epics:** TRN-EP-01/10/12/13. **Parent:** Sprint100 Draft PR #111 HEAD `4a969d4f2acc50907aeaf7846f2a767baf747a4c`, both exact Push #38387221139 and Mainline PR #38387270470 successful (14/14), preliminary review COMMENT only.

## Verified security weakness

The test-only member support-case event/audit journal is initialized by a PostgreSQL schema-owner datasource and **the same owner datasource was supplied to every support HTTP GET/POST**. The backend can therefore execute DDL or alter/drop its own append-only trigger and history, even though standard support operations need only case-header CAS and history/audit SELECT+INSERT. This differs from the older restricted clinical-center integration-test role. The exact fail-closed safety correction is to separate *schema initialization owner* from *support journal runtime identity* within the existing local ephemeral ASP.NET demo, without making a claim of fully least-privileged Production security.
