# TRN-TECH-038 — Durable synthetic cost-awareness provenance and replay journal

**Date:** 2026-10-10. **Stacked base:** Sprint28 PR #35, Draft/Open. Accepted Business scope: TRN-BIZ-050/051/052. Sprint28 produced pure in-memory version-bound cost choice observation and an explicitly disconnected Member Web. Sprint29 exercises **synthetic durable event lineage and negative tests only**, without enabling any actual member-choice button or accepting legal/financial obligations.

## Precise foundation

- New `PgSyntheticCostAwarenessJournal` in the already existing **nondeployable** `Taranom.ProofingJournal.Postgres` technical-test assembly, using an ephemeral CI PostgreSQL database. NO member web/network endpoint, BFF, authentication service, payment account, clinical contract or real data source.
- `RegisterAsync(SyntheticCostPreview)` accepts only a `test:` member, nonempty preview UUID, positive preview version and a **canonical builder-verified** five-share preview. Explicit `Missing` remains null (not zero), `ConflictingClaims` has no number, and `ProvisionalClaim` is *merely a fictional unverified source statement* — never a confirmed tariff, policy, wallet balance or member liability. Recompute the full input canonical fingerprint before registration; reject forged fingerprint, invalid state or source. Any later attempt to register the same preview UUID with changed member, version, amounts, fingerprint or sources is a **conflict**, not a silent overwrite. New versions require distinct preview IDs. Exact repeated registration is an idempotent replay.
- Each registered preview pins immutable `member_ref`, `preview_revision`, `preview_json` and `preview_fingerprint` in `internal_test_cost_preview`. The *only* runtime-editable column is its monotonically advanced `choice_revision`. New records of claimed awareness/deferral/clarification are appended only through the existing pure `CostAwarenessRecorder`, after full history rehydration, and pin original **member, preview UUID, preview version and fingerprint**, expected revision, request UUID and claimed choice. There is **no actual user session, signature, consent or financially binding acceptance**. Replays are idempotent even after later events; stale, cross-member/preview and changed-fingerprint commands fail without mutation.
- Accepted choice writes commit transactionally: row lock on preview head, unique request UUID and revision, append-only event, paired audit record, and compare-and-set `choice_revision`. Simultaneous calls to different synthetic simulated replicas serialize. Audit insertion failure rolls back event and head. A restricted CI-only role gets SELECT/INSERT on preview, UPDATE only on `choice_revision`, and SELECT/INSERT on event and audit; no UPDATE/DELETE on accepted records. Trigger also blocks ordinary owner UPDATE/DELETE and prevents modification of immutable preview fields. There is no claim this protects against privileged DBA disabling triggers.
- Before **even an exact replay**, read full preview JSON, rebuild its canonical fingerprint using `SyntheticCostPreviewBuilder`, replay all recorded commands via `CostAwarenessRecorder.Record`, and compare per-event SHA-256 digest, revision, request identity, paired audit and projected head revision. Tampered digest, missing audit, malformed JSON or inconsistent history fails closed with `TEST_COST_AWARENESS_JOURNAL_CORRUPT`. SHA-256 is **unkeyed internal detection**, not externally trusted evidence, independent digital signature or regulatory compliance.
- No invalid/denied commands are stored as accepted events; this is not a full regulatory-grade denial log. Registration is a technical snapshot pin, NOT an audit of verified source documents. The method only observes caller-claimed `test:` data and is prohibited from promoting it to real financial eligibility.
