# TRN-TECH-052 — Historical member-credit period review (synthetic read projection)

**Date:** 2026-10-11. **Status:** test-only technical contract, not operational authorization. **Business:** accepted TRN-BIZ-003/005/006/012/013/014/015/016/024/026/029. **Backlog:** TRN-EP-03/08/13. Stacked Sprint 43 on Sprint 42 PR #49.

## Product gap, existing code reused
A user journey must distinguish *an original formally effective membership activation*, *initial 90 complete days for treatment-credit use*, *membership lapse where new accrual stops*, *reactivation without inventing a fresh wait*, and *late-recorded benefits attributable to historically valid membership* (after separately authorized review). The app's membership/credit pages currently show none of these distinctions. Implement without a new journal or reimplementing the already tested `MembershipWaitingPeriod`, `SyntheticMembershipCoverageWindow` or `LateEvidenceWorkItem`/Postgres journal. No monetary allocation formula, legal reviewer, payout or current membership status is invented.

`SyntheticCreditPeriodReviewProjector` is an **INTERNAL pure synthetic-only** read assembler. It accepts a test member, caller-claimed history of `SyntheticMembershipBoundary` and a batch of test-only income-source claims (IDs, exact half-open attribution periods, source revision, claim-received time, independently **claimed** evidence-review status), and explicit observation instant. Requires at least a closed initial activation/nonrenewal pair to validate timeline through the preexisting `SyntheticMembershipCoverageWindow`; otherwise returns `EvidenceInsufficient`. Fail-closed validation of the full history includes marker revisions/order/owner/event UUID and real-source rejection. It uses existing `MembershipWaitingPeriod.Observe` for the **hypothetical** first activation temporal threshold, never issuing a new wait on reactivation.

Each claim is assessed with the existing coverage observer: prior closed membership period = unverified review prerequisite; closed lapse period = no fabricated new accrual; crossing membership/lapse = cannot silently split; open/latest interval = insufficient historical proof; recorded before attribution period closes = premature. Even a caller-claimed Confirmed review returns only `HistoricalMembershipEvidencePresentOnly`, not actual entitlement, financial award, credit posting or authorization. Duplicate claim IDs and same exact source revision + attribution window are rejected before projection. Distinct source versions remain separate unverified claims and cannot be summed. Fingerprint is canonical/invariant to batch claim ordering, binds complete source and marker metadata, and is **not a signature nor legal financial attestation**.

No real membership operator, activated subscription, verified paid fees, consent, income source, amount/currency, balance, reviewed eligibility, real financial transaction, wallet mutation, real dispute workflow or legal evidence API exists here. Historical observation is not adjudication and **the 90-day clock is not proof of spendability**. Sponsor/employer never acquires individual credit/control via paying subscription.
