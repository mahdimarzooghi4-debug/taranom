Date: 2026-10-23. Business scope TRN-BIZ-046/047; medical/privacy and institutional-authority boundaries remain TRN-BIZ-035/036/041/043/045. This is an engineering test-only continuation of TRN-TECH-115/172/184/185/189/198, NOT medical, legal or external operations approval.

## Product gap and precisely limited workflow
The Member→Center synthetic nonclinical coordination request already has a manually transferable source-pinned locator (Sprint 189). The same PostgreSQL care journal supports unverified contact-note and opaque clinical-source-reference claims created by either interface, but Center has no equivalent human-carried locator for the **last recorded follow-up claim** that Member can independently confirm. The Member can manually read raw history, but cannot intentionally confirm a specific returned claim's UUID/action/opaque reference against its exact source revision. Add one **reverse technical return**, not an actual Center communication, professional medical reply or verified actor identity.

## Center export
After a human-triggered **source-validated READ** of a nonempty synthetic test case with at least one follow-up and no pending/uncertain write, Center can manually copy one read-only JSON locator. Only the **last persisted** event is eligible; it must be `RecordUnverifiedCoordinatorContact` or `AttachUnverifiedClinicalSourceReference`, with valid test-only actor/source refs and bound original root UUID and member/request lineage. Fields (exactly eleven): `format='TRN-TECH-199-TEST-CARE-CLAIM-RETURN'`, `version=1`, `caseRef`, `memberRef`, `originalMemberRequestRef`, `rootRequestId`, `revision`, `claimRequestId`, `claimAction`, `claimedActorRef`, `claimRef`. No real name, clinical payload, claim of sending a message, signature, token or persistent browser storage. Changing case, source failure, new POST or an unresolved ACK immediately hides prior receipt. A previously recorded event is **not evidence that any Center staff created or delivered it**; the ticket is simply a bookmark of the observed journal tip.

## Member manually reattests original source
The Member tester explicitly types/chooses exact synthetic `caseRef` and claimed `memberRef`, pastes the ticket into the existing nonclinical coordination UI and clicks a **single separate GET-only confirmation**. No automatic receipt import or data sharing. Before making any request, the parser rejects oversized/missing/extra-key/wrong-format/version/real refs, invalid v4 UUID, noninteger or insufficient revision, wrong event action, actor, and claim ref, as well as case/member mismatch with the tester's manually selected values. Then re-read **only** the original GET `/internal/demo/v1/care-coordination/{testCaseRef}`, which replays the full immutable event and audit journal through restricted READ ONLY PostgreSQL. Require its `outcome=READ`, exact case/member/ref/root request, latest revision equal to receipt, exact **last event** UUID/action/claimed actor/source ref/lineage and all 13 real-world denial flags. A structurally valid but forged root, wrong claim, wrong member or stale receipt must fail closed even if an ACK or prior cached state appears successful. Explicit fresh Center source reading and newly exported receipt after an intervening append is required. On import start or failure remove any prior actionable snapshot/history/confirmation rather than relying on the old state. Existing member `uncertain` exact-command UUID latch prevents imports and remains the only replay recovery channel. Import never issues a POST or implies medical decision, contact delivery, discharge, continuity approval, consent, provider assignment or legal notification.
