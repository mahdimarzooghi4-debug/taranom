# TRN-SP-03 — Denied-command audit hardening (synthetic only)

- Date: 2026-10-10; applies to Draft/Open PR #9 at the current SHA after exact-head CI.
- Dedicated `internal_test_proofing_denial` stores **a random attempt UUID, a synthetic `test:` case reference, request UUID, known rejected outcome code, and observed case revision**. No command JSON, identifiers, authentication assertion, provider text, clinical/insurance/finance data or raw failure details are saved.
- **Correct replay** is idempotent rather than denied: it creates neither another accepted event nor a denial. Conflicting duplicate keys, invalid commands, stale revisions and disallowed correction attempts are counted as **rejected** and generate a separate append-only denial record.
- The provisional case creation transaction is rolled back **before** denied-attempt logging. A rejected request cannot create a new case or accepted event. If the denial audit insert fails, the operation raises an error instead of returning an unlogged denial.
- Rejection audit uses an independent committed insert and is not represented as accepted state or proofing evidence. The test runtime database role may SELECT/INSERT but never UPDATE/DELETE the denial ledger; the test schema owner additionally triggers rejection on ordinary row UPDATE/DELETE. A PostgreSQL superuser can override these controls; this is **not** Production compliance evidence.
- **Limitations remain explicit:** invalid/unscoped case references and database corruption fail before the denial-audit path, and the audit has no authenticated actor/tenant linkage. This is **not** a complete access audit, does not authorize real reads, and does not replace a contractual IdP, consent policy, immutable external audit sink or source attestation.
- The unchanged in-memory reducer remains the authority only for deterministic *synthetic* transitions. The operational authorization and legal obligations of rejected attempts require further design and independent security/legal review. PR #9 remains Draft/Open; no Merge, Stage, QA, Release or Production.
